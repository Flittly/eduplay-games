# 省级行政区识别

EduPlay 平台游戏插件（iframe 型）：显示省级行政区轮廓，学生从候选项中选出名称，
可查看地理/文化提示，答完一局后把成绩回传平台积分系统。

## 玩法（v0.1.2）

- 每局默认 10 题，可改为 20/34 题。
- 每题展示一个省级行政区轮廓与四个选项。
- 可点击「提示」，逐步显示该省的几条地理文化线索。
- 答对得基础分；答错和使用提示会扣分，单题最低 0 分。
- 结束后通过 `GAME_COMPLETE` / `GAME_SESSION_COMPLETE` 与平台结算积分。

## 数据来源

- 省界路径**与「行政区拼图」同源**：`scripts/prepare_data.py` 读
  `province-puzzle/src/data/province.json`（Albers 等积圆锥投影、1200 单位宽），
  只去掉本游戏用不到的南海小地图 `inset` 字段。
  ⚠ 它**不直接读 shapefile** —— 上游那份由 `province-puzzle/scripts/prepare_data.py`
  从「2022 年中国省市县行政区划数据 / 2022省级」生成。
- 因此本游戏与「行政区拼图」「山河三消」的省界坐标**逐字节相同**（34/34），
  三者的像素账可以互相参照；`prepare_data.py --check` 会把这条比对跑一遍。
- 题目提示综合初中地理教材与公开地理资料整理，适合初高中生使用。

## v1.1.0 —— 港澳轮廓细粒度化（两层根因）

用户反馈：「香港和澳门的轮廓也非常的粗，需要更加细致的数据来作为识别的轮廓。」

### 结论：两层问题叠加，只修任一层都不够

| 层 | 根因 | 修法 |
|---|---|---|
| **数据** | `provinces.json` 是 `province-puzzle` 的**派生副本**，但那个脚本只是个 29 行拷贝器、没有自检，上游 v1.0.0 修好港澳后**这里一直没重跑** | 把它升级成带自检的真生成器并重新生成 |
| **渲染** | `stroke-width` 是 **viewBox 单位**，而轮廓 svg 拿**该要素自己的 bbox** 当 viewBox 单独缩放 ⇒ 要素越小描边越粗 | 小要素改用**不随缩放走**的描边 |
| **取景**（渲染的子问题） | 取景边距里有个**常数 `+12`**，对澳门（长边 2.41）相当于框的 **96% 都是空白** ⇒ 轮廓只画成 18×27 px 的一颗小红点 | 小要素改成**纯比例**边距（去掉常数） |

### 实测像素账（真机取景框 512×300，单人模式）

| | 形状 px | 描边 px | 描边/形状短边 |
|---|---|---|---|
| 澳门 · 修之前 | 11×23 | 22.8 | **200%**（一整块实心红方块） |
| 澳门 · 只修数据 | 18×27 | 22.4 | **125.8%**（仍然是一块红） |
| **澳门 · 修复后** | **107×259** | **1.5** | **0.88%** |
| 香港 · 修之前 | 95×78 | 17.3 | **22.2%** |
| 香港 · 只修数据 | 102×84 | 16.7 | **20.0%** |
| **香港 · 修复后** | **306×251** | **1.5** | **0.60%** |
| 上海（未改动，作对照） | 125×146 | 10.8 | 8.7% |
| 内蒙古（未改动，作对照） | 275×241 | 1.2 | 0.5% |

⇒ **「只修数据」那一行和「修之前」几乎一样** —— 光换数据，屏幕上一点改善都没有。
澳门更极端：旧数据把它的外环压成了**零长度路径**
（`d` = `M727,740L727,740L727,740L727,740Z`，8 个顶点只有 2 个不同坐标），
所以只把描边调细，结果会是**画面上一片空白**。

### 判据：为什么不用「红色像素占比」

第一版断言写的是「轮廓卡里红像素占比 < 0.35」，实测 44.5% 判红 —— **是尺子错了**：
香港 34 个岛的海岸线极曲折、周长/面积比高，1.5 px 的细描边总面积本来就和填充同量级。
改用一个**匹配物理尺度**的量：**描边屏幕宽度 ÷ 形状短边屏幕宽度**。

⚠ 还有一条同源的坑：`vector-effect: non-scaling-stroke` 时描边是**屏幕像素**，
**不能再乘缩放**（`stroke-width × k` 的公式只对普通描边成立）。漏了这个区分，
1.5 px 会被算成 37.6 px，得到一条假失败；更糟的是如果算出 `-Infinity`，
`1.5 / -Infinity === -0 ≤ 0.05` 会让断言**恒真**、变成假绿 ——
所以断言里显式带上了"度量是有限正数"这一条。

### 改动清单

- `scripts/prepare_data.py` 升级为带自检的真生成器（`--check` 可校验磁盘上那份是否过期）；
  `version` 字段改为从 `package.json` 读（原来抄着上游的 `0.3.3` 一路滞后）。
- 新增 `src/silhouette.ts`：`silhouetteViewBox` / `silhouettePathClass` / `TINY_BBOX = 22`
  —— 原来 `ProvinceQuiz.tsx` 与 `DualQuiz.tsx` **各存了一份一模一样的实现**，特例各写一遍必漏一处。
- `src/styles.css` 新增 `.silhouette-path.is-tiny`（`stroke-width: 1.5` +
  `vector-effect: non-scaling-stroke`），选择器**同时点名两个渲染点**、权重 (0,3,0)。
- `manifest.json` 补显式 `requiresRoster: true`。
