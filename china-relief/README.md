# 山河塑形·中国地形（china_relief）

> 把「四大高原 / 四大盆地 / 三大平原 / 27 条山脉」的卡片拖到中国地图上正确的位置，
> **放对的地方会按真实高程当场塑出分层设色** —— 全部归位之后，中国地势三级阶梯是学生自己拖出来的。
> 每放对一块就地弹出它的实景照片与成因讲解。点卡片也能主动查看讲解。
>
> `gameCode = china_relief` · `requiresRoster = false`（展示型游戏，打开即学，不做点名）
> · 版本号三处同步：`manifest.json` / `package.json` / `src/main.tsx`。

## v1.0.0 改了什么（三条都来自课堂反馈）

| # | 反馈 | 处理 |
| --- | --- | --- |
| ① | 「三维展示的时候有些卡顿，做成卡通的即可」 | 摘掉 three.js，整层换成 **Canvas 2D 俯视分层设色**（bundle 从含 three 的体量降到 **855 KB**）。核心机制不变：塑形后仍按**真实高程**落色档。 |
| ② | 「没有把地形拖到地图上的时候，点击地图上的位置不应该出现地形区的介绍」 | 删掉画布点击查询。此前随手点一下地图就会弹出「这里是太行山」——**等于把答案送到手上**。 |
| ③ | 「地形放置正确，中间应该弹出来关于地形的介绍」 | 归位即讲解：拖对之后在**舞台正中**弹出介绍卡（带遮罩、点遮罩/×/ESC/「继续塑形」都能关）。 |

> 为什么不再用三维：原实现是 480×358 的真实高程网面（约 34 万个三角形），
> 每帧要重算 17 万个顶点的高度与颜色、动画收尾还得重算法线（20~50 ms）。
> 而这个游戏真正要教的东西 ——「这块地按它真实的海拔被塑起来了」—— 并不需要透视相机：
> **分层设色 + 档间描边 + 北向明暗** 在俯视图上就读得出来，而且这正是地理教科书读地形图的方式。
> 着色因此退化成一次线性扫描，也不再依赖 WebGL（老机器的显卡驱动不会再拖后腿）。

## 积分规则

| 项 | 分值 |
| --- | --- |
| 地形区基础分 | 20 |
| 山脉基础分 | 12 |
| 尝试系数 | 第 1 次 1.0 / 第 2 次 0.6 / 第 3 次起 0.3 |
| 连击奖励 | 连续 3 次「一次答对」额外 +15 |
| 放错 | −5（**不**计入尝试次数，所以不会被一次手滑毁掉满分） |
| 要提示（在图上闪一下位置） | −8，并把该条目记成「多试了一轮」（随后放对只拿 6 成） |
| 分数下限 | 0 |

评级按**一次答对率**给，不是按绝对分数 —— 这样拖得慢不会吃亏。

### 提示里的「+N」必须等于记分板加的分（曾经不一致）

提示文案要报「这一次加了多少分」，而记分板上的数字由 `applyCorrect` 算。
这两处各写一个常数，就会出现「提示写 +20、记分板只加 12」——
用过提示的条目要乘 0.6 系数，学生一比对就发现对不上，然后就不信提示了。

现在只有一处算法：`game.ts` 的 `gainFor(state, id, kind)`，`applyCorrect` 复用它，
提示也调它。回归里用属性测试锁死（6 个状态 × 2 类 × 3 条目 = 36 组逐一比对）。

配套的一条坑：`handleDrop` 只在 `state.placed` 变化时重建，学生用过提示之后
`placed` 没变，闭包里拿到的 `attemptOf` 还是旧的。所以另有一份 `stateRef` 镜像，
提示取的是它的当前值。

## 数据管线（`/` 全离线，运行时不需要联网）

- **DEM 来源**：[AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/)（Terrarium 编码），
  公有领域、免 key。解码 `h = R*256 + G + B/256 − 32768`。
- **取景框**：73–136°E / 17–55°N（保证曾母暗沙以北、黑龙江主航道以南都在框内），
  **480 × 358** 格，约 11.9 km/格。
- **编码**：整数米 → `Uint16` 小端 → base64，整块 **476 KB**，内嵌进 bundle。
  不做 zlib：实测压缩率只有 0.77，却要把解码变成异步、换来一个 loading 态和一堆
  `await`，省那点体积不值这个复杂度。
- **陆地遮罩**：1 bit/格（放对但落在海里要拦住；**v1.0.0 起画布点击已整条取消**，
  这张掩膜现在只服务于「落点是否在陆上」的判定与渲染描边）。
- **区域位图**：**4 bit/格**，记「这一格属于哪个地形区」。见下面「为什么查位图」。

## 关键设计决策

### 为什么是「按 cos(36°) 修正的等距圆柱」，不是 Albers

游戏要把经纬度栅格上的 DEM **逐格**搬到像素上，并在同一套索引空间里做着色与落点判定。
等距圆柱下网格 `(i,j)` 与画布像素一一对应，全都退化成查表；换成 Albers 就得给每个
像素做反投影，精度省下的那点形变远抵不过复杂度。

x 方向乘 `cos(36°)` 之后，南北与东西的**地面米数比例**与真实一致 ——
这是「中国看起来没有被横向拉长」的关键。副产品：1° 经度 ≈ 90 km，
所以 `distanceHint` 里算距离用的就是 `dLon * 90`，和地图自己的横向缩放同源。

二维版把这条又简化了一步：`terrain.ts` 的 `layout()` 只算一次
`scale = min(宽 / SPAN_X, 高 / SPAN_Z) × 0.96`，`pick()` 与 `project()` 都是它的
线性反演 —— 没有相机、没有射线求交、也没有"按地表高度迭代收敛"。代价是失去了
旋转与缩放视角；收获是**判定坐标与学生看到的画面必然同源**，
而且回归里可以拿"画布上的陆地像素数"去对"掩膜算出的期望值"（±8%），
投影/缩放/掩膜三者只要有一个不一致就会红。

### 落点判定为什么查「区域位图」而不是「离中心点多近」

地形区是有面积的。学生把「塔里木盆地」丢到天山北边的准噶尔去，按中心距离可能
也算「近」；查位图则直接问「**这一格到底属于谁**」—— 判定口径和地图本身完全一致。

位图按「**小面积优先**」生成，于是柴达木盆地这种嵌在青藏高原内部的盆地也能各归各位
（不然一个格子只能写一个编号，柴达木会被青藏高原整个吞掉）。回归里有一条断言
专门验「各区格数之和 = 非零格数」，也就是**互斥**。

### 山脉为什么要「走廊 lift + 高斯 add」两层

全国 DEM 是 11.9 km/格，太行山、南岭这种宽 50~80 km 的山脉在这个尺度上只剩
三四个格子，**光靠 DEM 立不起来**。但**完全不用 DEM 也不行**——那样山脉就只是
一条按「叠加米数」上色的扁平色带，既不是起伏的地形，颜色也和它真实的海拔对不上
（秦岭真高 2000 m，画出来却是 0~680 m 的草绿）。

所以：

- `lift` 遮罩把**走带走廊**整条按真实 DEM 塑出来（半宽 0.42° ≈ 47 km，往外 0.08° 收干净）
  —— 太行山那道「山西高原 vs 华北平原」的断崖、台湾中央山脉，都是这么自己长出来的；
- `add` 再沿折线叠一条高斯脊（σ = 0.24°，峰 900 m），把脊线挑出来，让窄山脉在
  这个网格精度下也读得出「一条脊」。

⚠️ `add` **必须裁进走廊**（乘上 lift 遮罩）。不裁的话高斯尾巴会拖到 1.08°，而那里
`lift = 0`、着色退化成「只按叠加米数上色」——肉眼看到的就是山体外面围了一圈草绿晕。
这条是放大截图之后才发现的，缩略图上根本看不出来。

### 「海拔」与「视觉高度」是两份数组

`elevationOffset`（真值，进判定与读数）与 `verticalExaggeration`（仅渲染）必须分开。
`raw` 只读 / `alt = max(0, raw + offset)` / `visualY = alt * exag` 只在顶点处算一次。
混在一起会立刻产生「山高 9000 米」这类荒谬读数。

## 验证

两层回归，都是可复跑的脚本。

**① 纯逻辑（`npm run test:data`，62 项断言）** —— 不开浏览器、两秒钟跑完：

- 投影正反自洽、北在 `-z`、取景框四角落在世界矩形边界上
- DEM 解码长度/极值与声明一致 + 珠峰 7048 m、吐鲁番 0 m、上海 4 m、青藏内部 5305 m 抽查
- 陆地遮罩 0/1 + 占比 40.9% + 台湾/海南在境内、太平洋与孟加拉湾在境外
- **11 个地形区的锚点全部判定为「对」**（锚点落到隔壁那一格的话，这一关直接无解，
  而且界面上完全看不出问题）
- **27 条山脉的锚点全部判定为「对」** + 锚点压在各自走带上（离折线 <0.02°）
- 「最近的那条必须是它」：脚本自己去数据里找**真的会互相蹭到**的走带对
  （实测最容易被认错的是「大巴山脉」与「巫山」，差 0.544°）再断言
- 积分状态机：尝试系数、连击、放错不写 `attemptOf`、提示降档、下限 0
- **`gainFor` 与 `applyCorrect` 实际加分处处一致**（36 组）
- 落偏提示：四个方位**不能指反**（见下）

**② 真实渲染（Electron 加载真实 `dist/web`，65 项断言）** —— 见 skill `frontend-visual-verify`：

- 用 `sendInputEvent` 发真鼠标事件（down / move × 16 / up）拖卡片，不是 `dispatchEvent`
- 用 `capturePage` / `paint` 取帧做像素直方图（WebGL 走 swiftshader 软渲染）
- **点开卡片真的能看到照片**：`img.naturalWidth > 0`、src 指向 `assets/photos/qingzang.jpg`，
  同时断言"兜底文案那条优雅降级的路"仍然挂在 DOM 上（不能为了不让照片大红叉就把降级删了）。
  **这条是这一版才补的防线**，起因见下面「回归写成假绿的一次」。
- **38 张卡片的照片对着产物逐一点名**。缺一张不会报错 —— `onError` 会把它藏掉、
  换成「实景照片待补充」，界面上没有任何地方会指出少的是哪一张。
- **最强的一条是几何探针**：用产品自己按地表高度迭代收敛的 `pick()` 当高度计，
  同一个屏幕点，青藏高原隆起前后读到的纬度是 **32.50°N → 31.20°N（Δ = 1.30°）**，
  理论值 1.4°。这直接证明产品自己算出的三维地表高度真的鼓起来了。
  探针在画布外松手，所以两次探测都没落子（分数 12 不变），不干扰游戏状态。

### 回归抓到过的三个真问题（都不是写测试时就能想到的）

1. **落偏方向提示整体指反**。`distanceHint` 里 `dLat = anchor[1] - lat` 是「从落点走到
   锚点要走的位移」，符号直接就是该走的方向；实现里写成了落在南边提示「往偏南找」。
   学生照着走只会离目标更远，而界面上完全看不出是 bug，只会觉得「这提示没用」。
   修的是符号，同时补了四个方位的断言（既要报对、也不能同时报出反方向）。
   顺带发现合成方位拼成了「往偏南偏偏东方向找」——`join("偏")` 把两个「偏」叠起来了，
   改为中文习惯的「东南 / 东北」（**东西在前、南北在后**）。
2. **提示里的 `+N` 与记分板不一致**（见上文积分一节）。
3. **山脉是一条扁平草绿带**，且走廊外还有一圈绿晕（见上文山脉两层隆起）。

### 回归写成**假绿**的一次（这个更危险）

上一轮真机回归里有一条断言叫「实景照片缺失时有兜底文案（不是一片破图）」——
它一直是绿的，而那一轮的 `host/web` 里**根本没有 `photos/` 目录**：
`server.log` 里明明白白记着 `GET /web/assets/photos/qingzang.jpg → 404`。

问题在于断言问的是「照片丢了会不会优雅降级」，而不是「照片在不在」。
于是**一张照片都没有的情况下，整份回归依然全绿**。
假红只浪费一次排查，**假绿会把缺陷直接放进交付物**。

改法：断言换成期望行为本身 ——「真的解码出来了（`naturalWidth > 0`，src 指向正确文件）」，
再把兜底那条单独留一条断言守着。两条各管一件事。

### 回归写成假红的两次（记录，避免再犯）

- 「可见陆地像素必须变少」——直觉是高原抬高会遮挡北侧地表，实测是 `377628 → 379142`
  （**变多**）：新增的南坡/西缘可见面积大于被遮挡的北侧面积。断言方向反了。
- 「山脉走带主色必须变」——山脉在屏幕上只有约 30 px 宽，80×80 窗口的主色**永远**是
  带子周围的米灰。改成剔掉米灰像素后求**带子自己**的均值才测得到。

## 开发

```bash
npm install
npm run dev        # 本地调试
npm run build      # tsc --noEmit && vite build → dist/web/
npm run test:data  # 纯逻辑回归（会先用 rolldown 把 TS 打成 CJS 再跑）
npm run test:photos # 图源规则自测（**裸 python 就能跑**，见下）

```

`test:data` 的约定：本机没有 esbuild，用 Vite 8 自带的 **rolldown** 把 TS 打成 CJS
供 Node `require`。**改了 `src/game.ts` / `src/geo.ts` / `src/data/regions.ts`
都要重跑**，否则测的是上一版产物。

`test:photos`（`scripts/photo_rules.test.py`，16 项）守的是 `_is_bad_url()` 那组规则。
**它必须双向断言**：既要拦住真广告位（`/logo.png`、`/banner/promo.jpg`），
也要放行正常文件名（`Grasslands in Heshigten Banner.jpg` —— Banner 是内蒙古的旗）。
只测前一半的话，把规则收紧到什么都不放行也能全绿。
这条自测是因为那组规则**已经误杀过两次**才补上的，详见下面「图源规则的两代误杀」。

为此 `fetch_photos.py` 的 Pillow 导入做成了用时才报错
（`_need_pil()`）—— 规则自测根本用不到 Pillow，不该因为它跑不起来。

### 实景照片

脚本在 `scripts/` 下。**跑这些脚本要用带 Pillow 的解释器**
（裸 `python` 里没有 PIL，会直接 `ModuleNotFoundError`）：

```bash
PY="C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe"

"$PY" scripts/fetch_photos.py --sheet        # 补齐缺的，并出拼版缩略图
"$PY" scripts/fetch_photos.py --force        # 全部重取
"$PY" scripts/fetch_photos.py --only=taihang --force
"$PY" scripts/pick_photos.py --only=yinshan  # 出**检索结果**候选拼版（挑图用）
"$PY" scripts/sheet_selected.py --pinned     # 复核**已钉定**的 COMMONS_PICK 全部条目
"$PY" scripts/fetch_photos.py --avoid=<url片段> --force   # 拉黑某图源后重取
```

`pick_photos.py` 和 `sheet_selected.py` 是复核回路的两半：前者拼**检索结果**（挑的时候看），
后者拼**你钉死的文件名**（复核的时候看）。少一半的话，"钉进去之后到底下到了哪张图"
只能靠跑完整回归、再从截图里找，而截图里那张往往只有 300 px 宽。

`sheet_selected.py` 的 `--files=` 里，**文件名之间用 `|`，条目之间用 `;`** ——
不能用逗号，因为 Commons 的文件名本身经常带逗号
（`Xiangshui Creek, Wuying National Forest Park, Heilongjiang, China (6 September 2016).jpg`）。

主源是 **Wikimedia Commons 官方 API**，备源是百度图片。

为什么不是当初那套 360 图片接口：2026-09 实测 `image.so.com` 的接口**整体不通**
（`SSL: UNEXPECTED_EOF_WHILE_READING`），主源直接没了；而百度接口把返回的
**60/60 条**结果全打上 `isAigcEdit: true`（连百度自家 CDN 和知乎的真实照片也标），
这个字段已经没有区分度 —— 当初照旧拿它当一票否决，结果 38 张里 **25 张候选池被清空**、
一张都没抓到。Commons 的图是真实照片、有明确许可、标题就是山名，也没有水印图库和
「景区门票攻略」这类噪声。**教学产品要分发到学校，图源干净本身就是交付质量的一部分。**

#### 只收 JPEG

Commons 上的**地图、卫星拼接图、地形渲染图几乎都是 PNG**，实景照片几乎都是 JPEG。
这一条比任何标题关键词都管用：复核时看到「四川盆地」抓到一张英文地形图、
「台湾山脉」抓到一张分层设色高度图，两张都是 PNG。

#### 跨境山脉要查 `Category:`，别只搜关键词

小兴安岭的英文正名是 **Lesser Khingan**，而 `Category:Lesser Khingan` 只有 4 个文件、
其中 **3 个在俄罗斯**（犹太自治州、Облучье、一个采石场），仅存的中国照片是
1963 年神树镇的**生活照**（烟囱、木屋、人物），当风景照不合格。
自动检索的结果，正是一张西里尔文标题的俄方照片。

阴山也一样：`Category:Yin Mountains` 只有 2 个文件，但两个都真的在阴山
（其中「大青山一景」在包头石拐区，40.65°N/110.30°E，是真正的阴山·大青山段）。

结论：**能查到分类就先列分类成员**，比关键词检索准得多；
跨境山脉（小兴安岭 / 阿尔泰 / 帕米尔一带）尤其如此 —— 关键词会把邻国那一半捞进来。

#### 复核回路（这一步不能省）

`--sheet` 出的拼版必须**逐格目视确认**。Commons 的排序只能保证「标题里有这个地名」，
保证不了「这张图适合当教材」—— 实测「巫山」抓到巫山寺、「燕山」抓到燕山寺、
「阴山」抓到 `Yinshanosaurus`（一种恐龙，属名也来自阴山）、「祁连山脉」抓到 ISS 太空照。
**标题对、内容不对**是最常见的坑，重灾区是这几类：

| 现象 | 实例 |
| --- | --- |
| 同名寺庙 / 陵墓 | 「巫山」→ 巫山寺；「燕山」→ 燕山寺；「阴山」→ 阴山墓地 |
| 同名古生物 | 「阴山」→ `Yinshanosaurus`（恐龙，属名也来自阴山） |
| 城市全景，山只当背景 | 「阴山」→「呼和浩特北面的大青山」，画面九成是楼群 |
| 换了主体 | 「雪峰山」→ 树干树皮特写（标题是"雪松林"）；「xuefeng」→ 日本琴平神社 |
| 舷窗 / 舱内照 | 「浩良河镇航拍」→ 左上角带飞机翼尖，缩略图下还像卫星图 |

所以流程是：

1. `python scripts/pick_photos.py --only=<出问题的 id>` 出候选拼版；
2. 在拼版里挑出编号，用 `scripts/_cands.json` 查到确切文件名；
3. 把文件名写进 `fetch_photos.py` 的 `COMMONS_PICK`（**写死的文件名绝对优先，且不参与排序**——
   否则「阴山」挑的中文标题照片会被检索到的 `Yinshanosaurus` 挤下去）；
4. `--force` 重取；
5. `python scripts/sheet_selected.py --pinned` 把**钉死的那些**再拼一张复核，
   并确认没有"钉了 A 下到 B"的情况。

第 5 步别省：卡片上的照片框是 `aspect-ratio: 16/10` + `object-fit: cover`，
**竖构图的图会被居中裁掉大半**。挑图时要按裁完的样子判断（五营那张 1200×1500
裁成 1200×750 之后正好是"苔藓溪流 + 蕨类"，反而比原图更像林区）。

#### 图源规则的两代误杀（都静默）

`_is_bad_url()` 里那组"广告位"关键词误杀过两次，**两次都不报错**：

1. **拿整条 URL 做子串匹配**时，`"banner"` 命中了 `Grasslands in Heshigten Banner.jpg`。
   而 **Banner 是内蒙古县级区名的正式英译**（Heshigten Banner = 克什克腾旗），
   于是 Commons 上**所有关于内蒙古"旗"的照片都抓不下来**。
   表现只是挑定报 `pick-fail`，而 `fetch_one` 的挑定分支用 `except Exception: got = None`
   把原因吞了，看着像"网络不好"；更隐蔽的是 `rank_candidates()` 也用它，
   自动检索时这些候选是**静默跳过**的。修复靠的是把异常打出来逐层复现
   （`_download_best` 返回 None → 查池子非空 → 查 `_is_bad_url` → 命中）。
2. **改成"片段以 `/` 开头"之后仍不够**：`.../1/1a/Iconic_Mountain.jpg` 里
   第二个 `/` 后面就是 `icon`，照样中招。最终改成**完整路径段**（正则 + 边界：
   片段后必须紧跟分隔符或到结尾）。
3. 边界集合**故意不含 `_` 和 `-`**：那样 `Logo_Rock.jpg`（地名）会被误杀。
   取舍标准是 **"误杀比误放更糟"** —— 误杀是静默的，误放会在复核拼版里一眼看见。
   代价是 `logo_dark.png` 这类带下划线的 UI 资源拦不住，交给 CDN 那几条规则兜。

定稿后补了 `scripts/photo_rules.test.py`（16 项，`npm run test:photos`）双向锁住。

#### 四个必须注意的行为

- **图源记录必须合并写，不能覆盖。** `_photo_sources.json` 原来每次都是整体覆盖，
  于是任何一次 `--only=` 的局部重取都会把**其它条目**的记录抹掉（实测只剩 13 条）。
  改成"读旧文件 → `update` → 写回"。
- **收录条件不能按状态白名单。** 原来只收 `ok / ok-small / ok-relaxed / reuse`，
  而 Commons 主源返回的状态是 `commons` / `commons-pick`（来自 `_download_best` 的 tag）——
  于是**最主要的两种来源一条都没记**，38 张里只写进 14 条，而且少的正好是
  "人工挑定项"这批最需要留痕的。改成按事实判断：**图确实落盘了、且说得出它从哪来，就记**。
- **挑定失败不许静默退回检索。** 退回的后果是「本来挑好的图被一张更差的图顶掉」，
  而日志上只看得到一次成功的抓取。现在直接报 `pick-fail` 并计入「缺失」，
  让下一轮把它显出来。这条是踩过的：批量取图时三条挑定图连着撞 **HTTP 429**，
  而当时的代码正是静默退回，三张图被悄悄换成了别的。
- **429 的退避要比断连长得多**（按 `Retry-After`，默认 6 s × 次数递增）。
  条目之间也留 1 s 间隔，别把 API 打限流。

图源 URL 记在 `scripts/_photo_sources.json`。
