# 经纬度五子棋

在经纬线构成的 15×15 棋盘上轮流落子。横线是纬线、竖线是经线，每个交点就是一组经纬度坐标。
轮到学生时，必须在棋盘一侧**报出带半球的坐标**（如「北纬30° 东经100°」「南纬15° 西经25°」），
坐标正确且该点为空才能落子；先连成五子者获胜。

## 玩法

- 棋盘范围每局随机平移，可能整块落在**北纬 / 南纬 / 东经 / 西经**任一象限，
  也可能**跨赤道**或**跨本初子午线**；经纬线每隔 5° 一条，共 15 条。
- 红方 / 黑方轮流落子，先连成五子获胜。
- 落子必须写明半球，且正好落在格点上。接受 `北纬30°`、`30°N`、`N30` 等写法；
  棋盘不跨 0° 线时也接受裸数字（如 `30`），跨线时因为有两种读法会要求写明半球。
- **坐标有两种输入方式，随时可切**（`输入方式` 切换，默认手动输入）：
  - `手动输入`：自己从格线上读出度数并写出来 —— 练的是**看图说坐标**。
  - `下拉选择`：度数从下拉框里按 **5° 一档**挑一个，后面再单独选半球 ——
    练的是**听坐标找交点**（老师报「北纬30° 东经120°」，学生在下拉里找出来）。
    两条轴各一个下拉框 + 两个半球按钮；选到 0° 时半球按钮置灰并提示"不用再选半球"。
- **格线度数可分三档隐藏**：`全部标出`（15 条全标，先讲一遍）→
  `隔一标一`（默认，标 8~9 条）→ `只留锚点`（只标 3~4 条，其余靠数格子算）。
  无论哪一档，**赤道 / 本初子午线永远被标出**并画成加粗金线 ——
  它是学生唯一能无条件信任的锚点，藏掉它就把「数格子」变成了「猜格子」。
- 支持双人对战，也支持「学生 vs 电脑」人机模式。
- 教师可在游戏内自定义胜方、负方和平局的积分。

## 棋盘几何：为什么加南纬西经不用改棋盘

窗口跨度恒为 70°（15 条线 × 每格 5°），每局只随机平移窗口位置。支撑四象限的是一条不变式：

> **`latTop` 永远是窗口最北的一条纬线，`lonLeft` 永远是最西的一条经线。**

于是 `row = (latTop − lat)/5`、`col = (lon − lonLeft)/5` 对带符号的值天然成立，
棋盘几何完全不需要为南纬 / 西经加分支 —— 窗口平移与半球归属是**正交**的两件事。
这也是旧版（只有北纬、东经）的 5 档 / 23 档窗口在新版里全部保留、老棋盘仍然能开出来的原因。

经度窗口左沿上界取 110°E，是为了让右沿恰好落在 180°E：**窗口永不跨越 180° 经线**，
否则「左沿数值最小」这条不变式会在换日线上断裂。

## 坐标解析：三条刻意的取舍

1. **半球与负号不能同时出现**。`南纬-30` 互相矛盾，直接判错，而不是「以负号为准」。
   裸负号 `-30` 则**当作半球声明**处理（南纬30°）—— 不能 `Math.abs` 一抹了之，
   那会把「南纬30°」悄悄变成「北纬30°」，学生写错半球却落了子，比报错糟糕得多。
2. **棋盘跨 0° 线时拒绝裸数字**。此时 `30` 确实有两种读法，猜一个等于教错。
3. **写了本棋盘不存在的半球时单独给提示**，例如「本棋盘纬度只有南纬（南纬90°—南纬20°）」，
   而不是笼统地报「超出范围」—— 学生真正需要知道的是「这局在南半球，没有北纬」。

## 两种输入方式为什么共用一套校验

下拉选择**不另写一条"直接算行列"的捷径**，而是把两个选择合成一句手动输入也能识别的文本
（`composeDegreeInput` → `北纬30°`），再交给同一个 `parseDegreeInput`：

```ts
const text = inputMode === "type" ? latInput : composeDegreeInput("lat", pick.degree, pick.hemi);
const result = parseDegreeInput(text, "lat", range);   // 两条路走同一个校验
```

好处是**下拉框不可能成为后门**：它永远放行不了一个手动输入会被判错的坐标，
学生也不会遇到"同一个交点换个输入方式结果不一样"。纯逻辑测试里那条最强的断言就是这件事 ——
遍历 1357 档窗口 × 两条轴，把每条格线翻译成「度数 + 半球」再合成，必须解析回原值。

下拉框里那一列度数取的是格线度数的**绝对值**（升序去重）。窗口总是连续排布，
所以 |度数| 必然是 0,5,10,… 的连续等差数列 —— 学生看到的就是等间隔的一列；
而"在北纬还是南纬"是另一半考点，拆成第二个选择器才不会顺手把答案一起送出去。
跨 0° 线时同一个绝对值出现两次（+5 与 −5），去重后自然少于 15 档。

两个细节：

- **默认半球取"本轴真实存在的第一个半球"**，不固定写 N/E。单半球棋盘的默认值若写反，
  学生第一次点「确认并落子」必定吃一个错；而跨 0° 线的棋盘两个半球都存在，
  默认北纬，学生想去南边就得自己切过去 —— 考点一点没少。
- **落子后两个下拉框都清空**，逼学生重新看一次格线；否则连点两次「确认」只会撞上
  「该交点已有棋子」，把一次读书练习变成一次报错练习。

## 与平台的契约：`requiresRoster` 必须是 `true`

平台的判定式是（`frontend/src/pages/GamePage.tsx`）：

```ts
const needsRoster = manifest.requiresRoster !== false;
if (needsRoster && selectedStudents.length === 0) return;   // 干脆不发 GAME_INIT
roster: needsRoster ? selectedStudents.map(...) : []        // 展示型发空名单
```

`requiresRoster: false` 有**两个**后果：跳过选人页 + 只发空 roster。
对地球仪那类展示型游戏正合适；但本游戏是双人轮流报坐标，
一旦被写成 `false`，就会变成「没有选人页，GAME_INIT 里 roster 是空的，
而游戏自身的闸门是 `roster.length === 0` 就不渲染主界面」——
页面永久停在「正在等待平台下发学生名单…」，谁也进不去。**v1.0.0 就是这样上架的，已修。**

因此本游戏的 manifest 固定写 `"requiresRoster": true`（缺省虽然等价于 true，
但显式写出来才不会下次被人顺手改成 false）。仓库根的
`scripts/roster-guard.cjs` 会替机器对一遍这件事：

```bash
node scripts/roster-guard.cjs   # 源码要名单 ⇒ manifest 不许说 false；顺带查版本三处一致
```

## 开发 / 构建 / 打包

```bash
npm install
npm run dev          # 本地开发
npm run build        # tsc --noEmit && vite build → dist/web/
npm run test:data    # 纯逻辑回归（165 项）
```

纯逻辑（棋盘窗口、坐标解析、标签隐藏、下拉选项合成）全在 `src/geo.ts`，不依赖 React，
用 `rolldown src/geo.ts --format cjs` 打成 CJS 后由 `scripts/geo.test.cjs` 直接跑。
UI 与交互在 `src/GeoGomoku.tsx`。

真机渲染回归（Electron 指向真实 `dist/web`）：`.workbuddy/tmp/ggverify/shot.js`，158 项断言。
其中 A2 段专门守「平台不下发名单时不许变成死路」：容器用 `?roster=none` 复现
「平台压根不发 GAME_INIT」，再验证等待页给出的「试玩」出口能开局、
且平台补发真名单后真实学生会接管试玩名单（试玩不残留、成绩不上报）。
E2 / G2 段守 v1.1.0 的下拉选择：下拉里的度数必须**逐个等于**棋盘上那 15 条格线的度数、
必须是等间隔的、点完确认棋子必须落在所选那条线上，以及「切回手动输入后原功能完好」。

## 踩过的坑

1. **`Math.abs` 会把学生的负号吃掉**。裸 `-30` 在「只含北纬」的棋盘上若被归一成正 30，
   就成了静默接受错误半球。处理方式是先把负号**提升为半球声明**，再走正常的半球校验。
2. **报错文案里的半球名不能按纬度硬编码**。曾经写成 `hemiName(kind, "S")`，
   于是经度棋盘（东经110°—180°）填西经时会提示「只有西经」—— 把要告诉学生的那件事说反了。
   半球名必须从本轴**实际存在**的半球推出来。
3. **范围读数的两端顺序**：设置界面按「下限—上限」写（`南纬5°—北纬65°`，便于读成区间），
   棋盘按地理惯例排版（上北下南、左西右东，所以最上面一条是**上限**）。
   两处顺序相反是刻意的，回归里各有一条断言分别守它们。
4. **半球并列枚举按中文习惯排序**：说「北纬与南纬都有」「东经与西经都有」，
   不要按数值从小到大的区间读法写成「南纬与北纬」。
5. **回归脚本不要往产品里塞调试钩子**。棋盘范围靠覆盖 iframe 的 `Math.random`
   注入确定取值队列，再点「换一个范围」触发；标签从 DOM 里读，学生看到什么就断言什么。
   产品代码零改动，断言口径与学生一致。
6. **`grep -c` 匹配 0 行时退出码是 1**，串在 `&&` 后面会提前截断脚本 —— 排查时容易误判成「构建失败」。
7. 在 JS 字符串里嵌中文引号会被规范化成 ASCII 直引号从而截断字符串字面量，
   报 `SyntaxError: missing ) after argument list`。测试文案里统一用 `「」`。
8. **`requiresRoster: false` 只属于"不需要点名的展示型游戏"**。本游戏是双人 PK，
   误填这个字段会让平台跳过选人页并只发空名单，游戏侧就永久卡在等待页（见上文契约一节）。
   凡是源码里存在 `roster.length === 0` 渲染闸门的游戏，都不能填 `false`。
9. **别把"等平台的消息"做成唯一出口**。凡是要靠平台下发数据才能渲染的界面，
   都要有一条本地兜底路径，否则平台少发一条消息就等于整个游戏不可用，
   而且从游戏侧完全看不出是哪一步出的问题。本游戏的兜底是 2.5 s 后给出「试玩」按钮，
   并且判定顺序固定为 `真实名单 > 本地试玩 > 空`，让真名单永远能接管。
10. **两个分段切换框共用 `.hide-mode-switch` 类名**（v1.1.0 起）。坐标面板里现在有两个
    同结构的切换框（`格线标注` / `输入方式`），`document.querySelectorAll(".hide-mode-options button")`
    会一次返回 5 个按钮 —— 回归里那条「坐标面板上有三档格线标注切换」就是这么红的。
    定位要按**框标题文案**（`switchButtons("格线标注")`），别用裸类选择器。
11. **验证脚本里 `String.raw` 模板块内不能出现反引号**（注释里也不行）。本仓库的坐标面板
    助手函数整段是一个模板字面量，注释里写了一句带反引号的类名，直接把模板提前闭合，
    报 `SyntaxError: Unexpected token 'switch'`，Electron 连第一个断言都到不了
    （日志里只有一行 `App threw an error during load`）。这与坑 7（中文引号冲掉字符串边界）是同一形状。
12. **回归脚本挑测试点时，先排除 0° 线**。0° 不分半球：选 0° 时半球按钮是置灰的，
    「选半球」那一步变成空跑；断言还会因为 `toCn("0°")` 返回 `null` 而静默变红。
    另外要避开前面几段已经落过子的交点，否则先被「该交点已有棋子」拦下，
    「棋子落在所选格线上」那条断言就成了假绿。脚本里现在是按这两个条件扫出来的索引。
