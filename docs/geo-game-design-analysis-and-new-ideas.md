# 已有地理教育游戏设计分析 · 与新一代创意方向

> 对象：`eduplay-games` 仓库现有 12 个游戏（源码实测，非凭印象）
> 目的：① 归纳既有设计思路与核心玩法；② 在**同一主题族**内找出真正的空白；③ 给出可直接立项的新方向。

---

### 1.2 逐个体检

#### ① 行政区拼图 `province-puzzle` v1.0.0 — 1,135 行

- **玩法**：拖动省级行政区到地图正确位置；吸附阈值 `MIN_SNAP = 30`，过小图元（`TINY_BBOX = 22`）另有处理（港澳等）。
- **计分**：教师可自定义积分；右侧「学生排行榜」按**完成用时由短到长**排序（实测 UI 原文），带南海诸岛小地图。
- **设计取舍**：规则里带 `RULES_STORAGE_KEY` 持久化，说明设计者懂"教师调好的规则下次进课还得在"。
- **问题**：34 个图元一次全上，**难度曲线是平的**。没有分层，学困生第一次玩就是 34 个。

#### ② 省级行政区识别 `province-quiz` v1.1.0 — 1,804 行

- **玩法**：给轮廓选名称，`QUESTION_CHOICES = [10, 20, 34]` 三档题量。
- **亮点**：`hints.ts` 里每个省 **3 条递进提示**，风格是"文化名片式"——北京："双奥之城"；山西："因位于太行山以西而得名"。这是全仓库最好的一处教学设计，**提示不是给答案，是给记忆钩子**。
- **双人 PK**：`DualQuiz.tsx` 有三阶段——`arrange`（老师指定谁上左右两侧）→ `battle` → `result`。注释里写明动机："平台下发的名单常常不止 2 人，一堂课选 5、6 个学生很常见，而 PK 一次只能上 2 个"。**这是从真实课堂里长出来的功能**。
- **问题**：选项是文字名称，4 选 1，**猜中概率 25%**。学生能靠"哪个名字更眼熟"过关，不真认轮廓。

#### ③ 经纬度五子棋 `geo-gomoku` v1.2.0 — 3,715 行

- **玩法**：**这是全仓库最聪明的设计**。在经纬线棋盘上落子，必须先报坐标（带半球）才能下。棋盘可能整块落在北纬/南纬/东经/西经任一象限，也可能**跨赤道或跨本初子午线**。
- **为什么聪明**：常规地理题是"给出坐标，问这是哪"。五子棋把它翻过来了——**坐标是你落子的手段，不是被考的对象**。学生为了赢棋，主动去算"我要下在北纬 30° 东经 120°"，经纬度从知识点变成了工具。这就是"引擎 + 数据"的典范。
- **配置**：15/19/25 三档棋盘（每格 5°）、方形/圆形球面两种盘面、纸纹/卫星影像/夜晚灯光三种皮肤、格线标注三档隐藏、坐标可手写或下拉框按 5° 选。
- **问题**：门槛高——不会读经纬度就完全下不了棋，**没有"傻瓜入口"**。

#### ④ 山河三消 `shanhe-match3` v1.1.0 — 1,413 行

- **玩法**：集齐同一省份的**轮廓 + 简称 + 省会**三张卡牌即可消除。
- **结构**：`TRAY_SIZE = 6` 手牌槽、最多 3 次提示（`HINT_COST = 5` 分）、最多 3 次悔棋（`UNDO_COST = 2` 分）、历史栈上限 40。
- **亮点**：港澳轮廓用细粒度行政区边界，牌面上**海岸线与离岛可辨认**——说明"轮廓要够真"被当成了硬指标。
- **问题**：三要素匹配本质是**记忆配对**，玩两遍就腻了。属于"练习器"而非"游戏"，重复游玩动机不足。

#### ⑤ 地图图例消消乐 `legend-match` v1.1.0 — 2,343 行

- **玩法**：图例符号与名称配成一对即消除，配对成功的一对**在屏幕中央放大复现**（`FOCUS_MS = 1700`，也可点击跳过）。
- **关卡设计**：`junior` 每关对数 `[4, 6, 8, 10, 12, 14]`，`senior` 为 `[6, 8, 10, 12, 14, 16]`。**每关加量，难度曲线是全仓库唯一做对了的**。
- **数据**：73 个图例，9 大类（地形地貌 13、交通航线 12、资源能源 11、河流水域 10…），分 `basic` 54 / `advanced` 19 两层。
- **设计精髓**：那个"放大复现"是**必经的中间态**，不是一闪而过的动画。注释原话："复现这一下才是加深印象的关键"。**把教学动作做成游戏流程的强制环节**——这是值得复用的模式。
- **另一个细节**：注释里解释了为什么用 `key={mode}` 整体重挂载——"绝不会出现上半局初中组、下半局高级组"。这是被真实 bug 教育过的痕迹。

#### ⑥ 气象要素识别 `weather-quiz` v1.0.0 — 1,930 行

- **玩法**：看图认气象要素，100 题 = 初中 50 + 高中 50，另有 88 条图鉴。
- **内容深度**：初中覆盖天气符号、风向风力、天气现象、气候类型判读、等温线；**高中覆盖锋面系统、气压系统、大气受热过程、热力环流、三圈环流与季风、等压线判读、气象灾害**——已经延伸到高中必修一的核心内容。
- **数据质量**：每题带 `hints`（2 条）+ `explain`（1 句解析）。例：晴 → "符号里只画了太阳，没有云" / "云量不足天空的 3 成称为晴"。
- **问题**：纯 4 选 1 答题，**和 `province-quiz` 是同一套骨架**。两个游戏结构重复度高，是新方向要避免的教训。

#### ⑦ 山河塑形·中国地形 `china-relief` v2.1.0 — 7,548 行

- **玩法**：把四大高原、四大盆地、三大平原、东南丘陵与 27 条山脉拖到中国地图的正确位置，**放对一张就按真实高程隆起**并弹出实景讲解。
- **数据规模**：`regions.ts` 17 万字符，59 个条目——12 个地形区（含两条分界线："昆仑—阿尔金—祁连—横断"和"大兴安岭—太行—巫山—雪峰"）+ 27 条山脉 + 20 个城市锚点。锚点即"地图上写名字的地方"。
- **计分**（`game.ts` 有一段极好的设计说明）：

  | 事件 | 分值 |
  |---|---|
  | 地形区放对 | +20 × 尝试系数 |
  | 山脉放对 | +12 × 尝试系数 |
  | 放错 | −5 |
  | 连续 3 次一次答对 | +15 |
  | 用一次「看轮廓」提示 | −8 |

  尝试系数：第 1 次 ×1.0、第 2 次 ×0.6、第 3 次及以后 ×0.3。

  **为什么"放错"要扣分**（注释原文）："不扣分的话，学生的最优策略是把卡片挨个往地图上乱丢——反正丢错没代价，试 11 次总能试出来，地形区的位置反而学不进去。扣 5 分让'想清楚再放'始终划算，又不至于一次失误就打击积极性。"

  **这是整个仓库最有价值的一条设计经验**：分数不是奖励，是**引导学生采用正确学习策略的杠杆**。

- **模式**：`relay`（轮流答题）/ 指定答题人 / 图鉴三种。答题人条"点谁谁答"，轮流模式下也能手动接管。
- **命中判定**：`pick.ts` 三层规则（名字带 → 走带 → 区域），注释坦白了偏差点——"`长江中下游平原` 的锚点离 `大别山` 脊线只有 0.31°，比走廊半宽 0.5° 还近"，于是必须有第一条"点在名字上就看这条"。

#### ⑧ 口袋地形 `mountain-zones` v2.4.4 — 10,065 行

- **玩法**：三维等高线地形沙盘。先用**模板**（山地/丘陵/盆地）认清山峰、山脊、山谷、鞍部、陡崖，再到**真实 DEM** 上拖海拔、改纬度看垂直自然带更替。
- **规模**：12 个 DEM 数据集，每个约 17.5 万字符（含 8 个真实样本：贡嘎山、珠峰、梅里雪山、太白山、华北平原、内蒙古高原、川中丘陵、临汾盆地 + 3 个模板）。山体下叠等高线投影，可拉剖面多段对比。
- **垂直带模型**（`zonation.ts`，教学用简化但方向与课本一致）：
  - 山麓气温 `T0(lat) = 28 − 0.4·|lat|` ℃
  - 气温直减率 0.6℃/100m：`T(lat,h) = T0(lat) − 0.006·h`
  - **基带 = 同纬度的水平自然带** ← 这是"垂直地带性是水平地带性的缩影"这条结论的数学来源
  - 雪线经验式 `5000·cos^1.2(lat)`，再叠加季节位移（夏升冬降）
- **难得的克制**（注释原文）："带谱**不随季节改换**（同一海拔全年是同一个自然带，北京山麓不会夏天变成长绿阔叶林），季节只体现在三处：雪线升降、林线随之升降、植被季相。"

  **能把"什么该随参数变、什么不该变"写清楚，是这类模型游戏最关键的一步。** 很多教学游戏就是在这里翻车的——季节一动整条带谱都换，学生反而学错了。

- **`locations.ts` 里还有一段硬核取证**：为什么省份要手写而不是由省界多边形自动判定。因为省界数据（DataV，1:100 万）本身有公里级误差，而**梅里雪山取景中心离省界只有 0.86 km，且那条省界就是怒山主脊——山脊本身就是界线**。多边形判定落在哪一侧取决于几公里的数据误差，所以必须人工编纂。

#### ⑨ 寰宇地球仪 `earth-globe` v1.5.1 — 5,376 行

- **玩法**：公转四季、昼夜与晨昏线、经纬网与五带、全球时区与地方时。
- **交互**：左侧「演示台」三节——公转自转旋钮、**可拖动的太阳直射点回归运动曲线**（橙色点）、**极地投影**（自南北极沿地轴俯视，直接读出两极极昼极夜）；「关闭黑夜」一键整球受光；另有自由视角平移。
- **设计点评**：把"晨昏线"这个最难讲的空间概念，用一个**极地俯视投影**解决——从正上方看下去，极昼极夜的范围是个圆，一目了然。**换视角解决教学难点，比加文字说明有效得多。**

#### ⑩ 寰宇月球 `moon-globe` v1.4.7 — 4,855 行

- **玩法**：旋转缩放看月面；拖滑杆看月相盈亏；切到日地月系统看月球绕地公转；点月面红点读中国探月任务着陆介绍。
- **架构**：`moonPhase.ts` 管**几何**（经纬度→单位向量、月相公式，唯一真相源），`moonSites.ts` 管**内容**（文案与插图）。文件头的理由写得很清楚："几何会被回归判据逐条复算，改一个字都要重新取证；而文案是要反复打磨的。混在一个文件里，改文案时很容易顺手碰到几何。"
- **内容纪律**（注释原文）："文案里所有数字都取自任务公布值 / NASA PDS 收录值。写进教材的东西不要凭印象。"以及「玉兔二号」里程"措辞一律用'截至……'并给出年份，不要写死成'行驶了 1690 米'这种看起来像终极事实的句式。"
- **素材原则**："学生要看到的是'月球长什么样'，矢量插图再漂亮也只是我们画出来的。"——**能拿到真实照片就绝不用自绘插图**。

#### ⑪ 寰宇太阳系 `solar-system` v1.1.2 — 2,619 行

- **玩法**：八大行星轨道与自转、太阳与主要卫星、小行星带与柯伊伯带；可调时间流速，点击天体查看图文档案。
- **数据**：27 个天体（含 15 颗主要卫星），如木卫一·艾奥、土卫六·泰坦、海卫一·特里同——**连卫星都有档案**，内容深度够。

#### ⑫ 地貌人格测试 `landform-quiz` v1.3.0 — 1,852 行

- **玩法**：20 道题 → 五维属性 → 在 80 处真实地貌中找最接近的一处。
- **五维设计**（`dimensions`）：温度 / 起伏 / 质地 / 动态 / 水意，每维有 `lowLabel` / `highLabel` / `lowDesc` / `highDesc`。例：起伏 → "平和低调"（像平原与盆地，不争高低）vs "高远出众"（像高原与高峰，心气很高）。
- **题目形式**：不是知识问答，是**情境偏好选择**。"如果可以自由选一个地方长住，你更想选——低纬度的热带海岛（thermal +2, moisture +2）/ 中纬度温带草原（thermal −1, moisture −2）/ 高纬度冷凉小镇（thermal −2, moisture −1）"。
- **数据**：80 处地貌，国内 40 + 国外 40，每处带真实照片、经纬度、summary 与 intro。
- **为什么这个游戏值得单独研究**：它**完全绕开了"考试"框架**。学生不是在被测知识，是在做自我探索，地理知识以"我像哪里"的方式进入记忆。**这是 12 个游戏里唯一从"动机"而非"内容"入手的设计。**

## 第二部分 · 五个可复用的设计范式（这是最有价值的部分）

### 范式 A：把知识点变成工具，而不是考题

**代表**：`geo-gomoku`（坐标是落子手段）、`shanhe-match3`（三要素是消除条件）

> **判据**：如果把知识点从游戏里去掉，游戏还能不能玩？
> 能玩 ⇒ 知识点只是个"贴纸"，学生绕过它照样赢（`province-quiz` 的 4 选 1 就是这种）。
> 不能玩 ⇒ 知识点成了引擎的必要零件（`geo-gomoku` 去掉坐标就下不了棋）。

**这条判据应当作为新方向的准入门槛。** 现有 12 个游戏里，真正通过的不超过 4 个。

---

### 范式 B：把教学动作做成必经流程

**代表**：`legend-match` 的"配对成功 → 中央放大复现 1.7 秒"

> 大多数教学游戏把讲解做成"答对了弹个恭喜"，学生狂点跳过。
> `legend-match` 把它做成**必须经过的中间态**——想继续玩，就得看一眼那一对符号和解释。
>
> **可复用形式**：把"看一眼"这道工序嵌进循环的必经路径，而不是放在旁边的说明区。

---

### 范式 C：用分数引导学习策略

**代表**：`china-relief` 的 −5 分惩罚与"尝试系数"

> 分数不是奖励，是**行为塑形工具**。核心问题是："如果学生不学，他能不能靠试错过关？"
> 能 ⇒ 必须给试错加成本（`china-relief` 用 −5 分）；同时不能一棍子打死（尝试系数第 2 次仍给 6 成）。
>
> **新方向必答的一题**：我的游戏里，学生的最优策略是"学"还是"试"？

---

### 范式 D：几何与内容分离

**代表**：`moon-globe`（`moonPhase.ts` vs `moonSites.ts`）、`mountain-zones`（`zonation.ts` vs `view3d.ts`）

> 理由（注释原文）：几何要被判据逐条复算，改一个字都要重新取证；文案要反复打磨。混在一起，改文案时会顺手碰到几何。
>
> **这是工程纪律，但直接决定教学游戏的可靠性**——教学游戏最怕"界面看着对、物理算错了"，分离后几何可以脱离渲染跑单元测试。

---

### 范式 E：换视角解决教学难点

**代表**：`earth-globe` 的极地投影、`mountain-zones` 的剖面叠加

> 晨昏线/极昼极夜从正上方看一目了然；山脊山谷从剖面看一目了然。
> **学生听不懂，往往是视角错了，不是解释不够多。**
>
> 新方向遇到难点时，先问："换个视角能不能自解释？"再决定要不要加文字。

## 第三部分 · 三个已被验证有效的通用机制

这三点在 12 个游戏里反复出现，且都是被真实课堂逼出来的：

| 机制 | 落地形态 | 为什么有效 |
|---|---|---|
| **点名 + 轮流** | `session.order` 队伍、`relay` 轮流 / 指定答题人、点选切换 | 平台下发名单，一堂课 5~6 人上台是常态。没有轮转机制，第 3 个人起就无从上场 |
| **递进式提示** | `province-quiz` 每省 3 条文化名片式提示 | **提示给记忆钩子，不给答案**。比"正确答案是 XX"有用得多 |
| **图鉴随时可查** | `legend-match` 73 图例、`weather-quiz` 88 要素、`china-relief` 图鉴（出现 109 次） | 把"背不下来"从挫败变成"可以查"，降低门槛同时保留学习价值 |

## 第四部分 · 已覆盖 vs 空白（实测词频）

对全部源码 + 数据做了关键词统计，用于确认哪些主题真的没人做：

| 主题 | 出现次数 | 覆盖判定 |
|---|---:|---|

### 结论：三块真正的空白区

**空白一 · 水文与水循环**（洋流 0 次、水循环 0 次）
现有游戏把"水"只当作**地表符号**（河流图例、海陆位置），**从未把水当作一个运动过程**。而"水循环"是初中地理的必考大题，"洋流"是高中自然地理的硬骨头。

**空白二 · 人文经济地理**（城镇化 0、人口迁移 0、城市等级 0、产业 2）
12 个游戏全部是**自然地理 + 地图技能**。人文地理（人口、城市、农业工业区位、交通、区域可持续）**一处未占**。这不是能力问题，是选题盲区。

**空白三 · 地质地貌的"过程"**（荒漠化 0、水土流失 3）
现有 `landform-quiz` 是**结果**导向（"你像哪种地貌"），从未展示"地貌是**怎么变成现在这样**的"。外力作用、侵蚀搬运堆积、土壤形成——全是过程题，全没做。

> 💡 **另一个观察**：`weather-quiz` 与 `province-quiz` 结构几乎同构（数据 + 4 选 1 + 图鉴 + 双人），骨架重复度极高。**新方向不应再产第三个同骨架的游戏，而应产出新的"引擎骨架"。**

#### 【创想 1】水循环大冒险 🔥 最推荐

| 项 | 内容 |
|---|---|
| **对应空白** | 水循环 0 次 · 洋流 0 次 |
| **学段** | 七年级上（水循环）→ 高中（洋流、水循环的地理意义） |
| **核心玩法** | 玩家是**一滴水**。在「海洋蒸汽 → 水汽输送 → 降水 → 地表径流 / 下渗 → 地下径流 → 回到海洋」的循环图上**逐段推进**。每段路上做一次决策（"该下渗还是该变成地表径流？"），选错就走支路（比如被植物截留卡住、或者蒸发回大气）。走完全循环得满分，同时点亮的路径在图上**留下来**，最后拼成完整的水循环示意图 |
| **为什么这是最优解** | ① **把"图"变成"走过的路"**——课本上那张循环图是静态的，学生靠背箭头；这个设计让学生**亲自走一遍**，箭头顺序自然记住。② 完美符合**范式 A**：去掉水循环知识就完全玩不了。③ 母题天然可扩展到洋流（"你这滴水进入洋流了，现在是北大西洋暖流，下一站去哪"），**一套引擎吃两个知识点** |
| **实现难度** | ★★★☆☆（约 2,000~3,000 行，可参照 `legend-match` 的体量） |
| **技术要点** | 路径图用 SVG 贝塞尔曲线 + 节点状态机；**几何用纯模型文件**（照 `moonPhase.ts` 的做法），可跑 Node 单测 |
| **单机 / 多人** | 单机闯关 + 轮流答题（照 `relay`）。**加分项**：每位学生走出的路径**叠加画在同一张图上**，全班走完就是一张被填满的循环图——天然的课堂总结素材 |
| **避坑** | 别做自由物理模拟（水滴物理做不准又难玩）。**做成节点与路径的离散决策**，教学上还更清晰 |

#### 【创想 2】大陆漂移 · 拼板块

| 项 | 内容 |
|---|---|
| **对应空白** | 板块 33 次（只有名词，没有过程）；地质"过程"全部空白 |
| **学段** | 七年级（海陆变迁、板块运动） |
| **核心玩法** | **反向拼图**：开局是今天的七大洲，玩家拖动时间滑杆**往回走**，大陆会依照板块运动一块块拼回盘古大陆；再正向播放，看它怎么裂开、漂移、撞出喜马拉雅山。玩家要在若干时间点**把化石证据摆到正确的大陆上**（"这种舌羊齿化石为什么同时出现在南美和非洲？"） |
| **为什么值得做** | ① 现有 `province-puzzle` / `china-relief` 都是**静态归位**，这个是**动态演化**——同是拖放，但教学价值完全不同。② 时间滑杆是**已被验证的交互**（`earth-globe` 的旋钮、`moon-globe` 的滑杆、`solar-system` 的时间流速），复用成本低。③ "大陆在动"是学生最难相信的地理事实之一，**让大陆真的动起来**比讲十遍都有效 |
| **实现难度** | ★★★★☆（主要成本在古地理重建的多边形数据） |
| **技术要点** | 每个大陆一组"当前多边形 + 旋转平移参数"，按时间插值。**数据量比想象中大**，建议只做 4~5 个关键时刻（现在 / 5000 万年前 / 1.5 亿年前 / 2.5 亿年前盘古 / 4 亿年前），**不做连续动画** |
| **单机 / 多人** | 单机 + 化石证据的抢答赛 |
| **避坑** | 古地理重建学术上有多个版本（大陆位置有争议）。**必须标注"示意，非精确复原"**，并明确采用哪个版本——照 `moon-globe` 的"数字标来源"纪律 |

#### 【创想 3】城市生长

| 项 | 内容 |
|---|---|
| **对应空白** | 城镇化 0 · 城市等级 0 · 人口迁移 0 |
| **学段** | 高中（城镇化、城市空间结构、人口迁移） |
| **核心玩法** | 一座小城逐渐长大。玩家是规划者：**在图上划线**决定哪里修路、哪里建住宅、哪里做工业区、哪里留绿地。每回合人口按**迁移模型**流入（就业机会 + 环境质量 − 通勤成本），城市自然长成单核 / 多核 / 带状。**玩到第 N 回合要回答**："你为什么把工业区放在城市东南？"（答案要联系盛行风向与河流下游） |

| **单机 / 多人** | 单机 + **异步对比**（不同学生的规划方案并排放，比谁的城市更宜居）——这是本仓库最缺的"对抗式学习" |

### 立项三条硬标准（建议直接作为准入门槛）

1. **范式 A 检验**：把知识点去掉，游戏还能玩吗？能玩 ⇒ 打回重做。
2. **不重复骨架**：不能是"数据 + 4 选 1 + 图鉴 + 双人"的第 N 个复制品。要么填新主题到**已有**引擎，要么造**新**骨架。
3. **范式 C 自问**：学生的最优策略是"学"还是"试"？如果是"试"，必须加成本。

### 最推荐的三条路（如果只做三个）

| 排序 | 项目 | 投入 | 回报 |
|---|---|---|---|
| 1 | **五子棋新手坡**（创想 8） | 约 300 行 | 让已有精品真正被课堂用起来，性价比最高 |
| 2 | **水循环大冒险**（创想 1） | 2,000~3,000 行 | 填补最大空白，且可延伸洋流，一套引擎两个知识点 |
| 3 | **三消·人文地理版**（创想 6） | 主要是编纂数据 | 用现成引擎快速补齐人文地理，边际成本极低 |
