# 地图图例消消乐（legend_match）

> 把地图上的**图例符号**和它的**名称**配成一对就能消除。每配对成功一次，
> 这一对会在屏幕中央**放大复现**一遍（符号 + 全称 + 类别 + 一句话解释）——
> 复现这一下才是加深印象的关键，所以它是必经的中间态，不是一闪而过的动画。
>
> `gameCode = legend_match` · `requiresRoster = true`（进入前由平台下发学生名单，
> 单人模式逐个学生上场记分、PK 模式两人一局擂台上台）
> · 版本号三处同步：`manifest.json` / `package.json` / `src/main.tsx`。
>
> **v1.1.0（本次）**：① 73 个图例**从自绘 SVG 全部换成真实图片素材** ——
> 教材图抠图（线条类 / 面状符号）+ Iconify 图标库（`mdi` Apache-2.0 · `maki` CC0 ·
> `game-icons` CC-BY-3.0 已署名）+ 按教材规范补绘，统一重建为 **512×512 透明底 PNG**
> （符号长边占画布 78%、线条统一到长边的 6.3%）；② **底卡改由 CSS 统一提供** ——
> 牌面 / 放大卡 / 图鉴缩略 / 图鉴详情四个展示位共用同底色、同边框、同内边距、同内凹底槽
> （v1.0.0 是把底卡画进 73 张 SVG 里的，改一次要改 73 处）；③ 顺手修掉两个真缺陷 ——
> **方形符号在牌面上被 `overflow:hidden` 平切**、**底卡内边距写百分比导致实测两拨值**；
> **玩法、关卡、计分、题库与图鉴筛选一行未动**。
> 详见 `CHANGELOG.md`（每一次更新收尾都出「比上版改了什么」）。

## 两个组别

高级组**包含**初中组的全部 —— 不是两套互斥的题库。理由有两条：
学生升组不丢基本盘；两组的分数才可比（同一个分数在两组排行榜上不是同一个意思，
所以组别**只在大厅选一次**，进游戏后只读显示，要换就退出去重选）。

| | 初中组 | 高级组 |
|---|---|---|
| 图例 | 54 条（`tier: "basic"`） | **73 条（全部）** |
| 关卡对数 | 4 / 6 / 8 / 10 / 12 / 14 | 6 / 8 / 10 / 12 / 14 / 16 |
| 整局对数 | 54 对（108 张卡） | 66 对（132 张卡） |
| 候选窗口下限 | 3 类 | 2 类 |
| 面向 | 课本正文必会的常用图例 | 含细分辨形条目，同类干扰更强 |

难度不靠"牌更多"单独支撑 —— 更要紧的是**同类干扰**：高关卡把候选池收窄到 2~3 个类别
（比如全是交通类），一堆长得像的符号混在一起才真正考人。
实测拥挤度（本关对数 ÷ 抽到的类别数，60 个 seed 取平均）：

| | 第 1 关 | 2 | 3 | 4 | 5 | 第 6 关 |
|---|---|---|---|---|---|---|
| 初中组 | 1.29 | 1.51 | 2.24 | 3.33 | 4.00 | 4.67 |
| 高级组 | 1.34 | 1.77 | 2.65 | 4.00 | 7.00 | 8.00 |

窗口宽度公式 `max(minWindow, ⌊类别数 × 0.7^关卡⌋)`（用 `floor` 保证单调不增）。
**"窗口够厚"不是靠 `minWindow` 保证的** —— 靠的是"只在够厚的起点里轮转"（见下节）。

## 三种玩法

| | 说明 |
|---|---|
| 单人闯关 | 逐个学生上台打完整 6 关，自动记分与排名；每关 3 次提示（−30 分/次），配错 −20 分并中断连击；关末可「提前结算，交成绩」（只在本关已完成时出现） |
| 双人 PK | 共享一副牌面（第 2 关的强度）轮流出手，配对成功 +10 分并继续出手、配错换人；三阶段：出战安排（左/右席 + 候场队列）→ 对战 → 本场结果（输者下场、候场队首上台） |
| 图例图鉴 | 按**范围**（全部 73 / 初中必备 54 / 进阶条目 19）×**类别**（9 类）筛选，点卡片看放大符号与说明；「全部」档下 19 条进阶条目挂金色「进阶」角标 |

cd scripts/assetbuild && python spec.py
# 映射表缺失 / 多余、图标不存在、图标碰撞（同一条图标给了两个图例）、抠图文件缺失、来源分布

2. **`spec.py` 的五项自检全绿**（映射表不多不少、图标都在、无碰撞、裁片文件都在）；
3. **每条图例都要声明 `tier`**，且 basic / advanced 必须是 **54 / 19** ——
   这条由 `npm run test:data` 守（不在 assetbuild 里）。漏一个 `tier` 会静默落进 basic，
   把两组的分界线悄悄挪掉。

## 一条踩过的坑：末关反而更松

旧代码的窗口起点是"关卡号 % 类别数"，类别按条目数降序排 —— 越往后轮到的类别越薄。
薄到凑不满本关对数时，旧代码会**临时并入更多类别**，窗口实际变宽、拥挤度反而下降：

| | 旧写法 | 新写法 |
|---|---|---|
| 初中组末关拥挤度 | **3.56**（低于第 5 关的 4.00） | **4.67** |
| 高级组末关拥挤度 | 5.33 | **8.00** |
| 触发补类别的关卡 | 初中组第 6 关 / 高级组第 5、6 关 | **0 关** |

修法：把窗口起点限制在「窗口自身条目数 ≥ 本关对数」的那些位置上 ——
窗口一定够厚 ⇒ 永不触发补类别 ⇒ 窗口宽度就是设计值 ⇒ 曲线干净。
轮转本身保留（条目少的类别**照样会被轮到**，只是不会让它独自在末关扛 16 对的量）。

判据里应对应有一条 **"抽到的类别不超出窗口"** —— 一旦出现窗口外的类别，
就说明补类别被触发了。**这条是唯一能咬住它的判据**：末关拥挤度 ≥ 5 之类的下限判据
在旧写法下照样能过（高级组旧写法末关 5.33 仍然 ≥ 5）。

## 上架

按仓库统一的 `.workbuddy/tmp/publish_<name>.py` 一条龙（zip → `POST /admin/games/{code}/packages`
→ `PATCH .../status ACTIVE` → `POST /store/games/{code}/package-install`）。
**`package-install` 那一步不能省** —— manifest 读的是 `plugins/installed/…` 那一份，
只上传不 install 的话商店里点"开始游戏"拿到的还是旧包，**成功判据是返回一个新的 version**。

```bash
python .workbuddy/tmp/publish_legend.py --pack      # 只打包 + 包内自检
python .workbuddy/tmp/publish_legend.py             # 打包 + 双端上架 + 双端对账
python .workbuddy/tmp/falsify_legend_needles.py     # 反证：判据真的会红吗
```

### 本游戏的指纹要分三张表（踩过一次）

**图例名不在 JS 包里。** 它们在运行时按需 `fetch` 的 `web/data/legends.json` 里
（`src/data.ts` 的 `useLegends`）—— 实测 73 个名字只有 5 个因别处文案巧合出现在 JS 中。
所以把「居民点」「高速铁路」当 JS 指纹会得到**一张永远找不到的假表**。正确分法是：

| 表 | 管什么 | 举例 |
|---|---|---|
| `JS_NEEDLES` | 界面结构 / 文案 | `lobby-tier`、`data-tier`、`game-mode`、`初中组`、`[4,6,8,10,12,14]`、版本串 `1.1.0` |
| `CSS_NEEDLES` | 样式写法 | `.mode-cards.is-tier button[aria-pressed=true]:after`、`--card-pad:6px`、`grid-template-rows:minmax(0,1fr)` |
| `DATA_NEEDLES` | 题库内容 | `"居民点"`、`"资源与能源"`、`"tier"`、`.png` |
| **`GONE_CSS` / `GONE_DATA`** | **v1.1.0 删掉的东西**（反向表） | `--card-pad:clamp`、`.svg` |

两个压缩后的**写法陷阱**（写错 = 恒红假判据，由反证脚本里的 C 组固定住）：

- 属性选择器的**引号被去掉**：产物是 `[aria-pressed=true]`，不是 `[aria-pressed="true"]`。
- 伪元素被写成**单冒号** `:after` / `:before`，不是 `::after` / `::before`。
- **（v1.1.0 新）`rgba()` 被压成 8 位十六进制**：源码写 `rgba(26,26,26,0.07)`，
  产物里是 `#1a1a1a12`。按源码里的 `rgba(...)` 写 CSS 指针 = 恒红。

### 删除型改动必须另立「禁表」

v1.1.0 把 73 个图例从 `.svg` 换成了 `.png` —— 这是**删除型改动**：
删掉之后少了一批字符串，**任何「必须有」的检查都不会红**（正向表照样全绿）。
所以另立了两张反向表，查"该删的真的找不到"：

| 禁表 | 内容 | 为什么 |
|---|---|---|
| `GONE_CSS` | `--card-pad:clamp`、`--card-pad:4%` | 百分比内边距实测是**两拨值**（缩略图 4.64px / 其余 8px），必须回不去 |
| `GONE_DATA` | `.svg` | `legends.json` 里一条 `.svg` 引用都不许剩（73 条全是 `.png`） |

外加包级禁表（`pack()` 里）：`web/assets/legends/` 下 **0 个 svg、73 个 png**，
且包内除 `web/cover.svg` 外**没有别的 svg**。

**反向表的反证要用「塞回去」（append），不能用「删掉」（drop）** ——
只做 drop 的夹具永远验不到禁表（它只会让正向表红）。

还有一条教训：`data-mode` 曾被我当成新指纹，**反证时拿真实上架过的 0.0.1 旧包一跑却没红** ——
因为大厅的**玩法卡**（单机闯关 / 双人 PK / 图鉴）早在 0.0.1 就用 `data-mode` 了。
⇒ 核指纹要核两件事：**①产物里有没有；②旧版本里有没有**。只核第一件会收进一堆废指针。
v1.1.0 照这条办了：11 条底卡 CSS 指针在**真实 1.0.0 包里一条都找不到**（反证脚本 A 组）。

### 反证夹具必须锚在「选择器 + 规则体」上

v1.1.0 又踩了一次"夹具打偏"：想证明「底卡共用规则给了底色」这条判据会红，
写成 `css.replace("--card-ground:#fbf6ea", "#eee")` —— 打中的是 `:root` 里的**变量定义**，
而判据读的是**共用规则的规则体**。结果是：变量没了、判据却依然绿，
`detail` 里写的是「CSS 缺 `--card-ground`」而不是「成对判据缺」。
⇒ 锚点要写成 `选择器 + "{background:var(--card-ground)"` 这种**独一无二**的片段，
而且**先 `assert` 锚点存在**（锚不到就是空操作，会伪装成"判据不灵"）。
