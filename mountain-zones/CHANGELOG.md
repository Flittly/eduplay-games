## v2.4.4 改了什么（2026-09-22）

**三个模板地形重建，撤掉三处结构异常**（用户逐一点名）。只动数据层
（`scripts/gen_templates.cjs` → 重产三个 DEM），界面一行没改。

### ① 模板山地：山谷不再是"人工河道"

| | v2.4.3 | v2.4.4 |
|---|---|---|
| 剖面 | cone **尖底**（中心线是折角，渲染成刀刻线） | **圆底锥** `rcone`（0.4 格圆角，C¹ 连接） |
| 深度 | 全程等深 520 m | **沿程加深**：源头系数 0.42 → 谷口 1.0（480 m） |
| 宽度 | 全程等宽（半宽 700 m） | **沿程加宽**：半宽 4.6 → 6.6 格 |
| 走向 | 三站几乎共线 | 六站**蜿蜒**，谷口伸到图幅边缘 |

山脊、断层崖、两峰、鞍部**一个参数没动**（生成器里那几项原样）。
判型/部位自检不变：峰 3 / 脊 76 / 谷 55 / 鞍 2 / 崖 7，最大坡度 76.6°、suspect 0。

### ② 模板丘陵：三条冲沟从"渠道"变回"沟"

三条沟仍然走丘间廊道、条数不变，但从「等深 140 m、笔直、尖底」改成：
**5~6 站蜿蜒**（廊道中心线 ±4 格内摆动）+ **圆底**（0.25 格圆角）+
**两端收浅到一半**（`0.5+0.5·sin(π·pos)`，沟首沟尾"长进"地形里）。
沟深 140→165、半宽收在 2.2 格 —— 这是判据逼出来的：TPI 邻域 24 格里
16 格在中心线 ±1 格内，谷剖面必须在 1 格内掉下 ≥0.2×全深，
**"宽平底"的 U 形谷会让山谷检不出**（第一版半宽 2.8 格实测谷点=0，就是它）。

### ③ 模板盆地：撤掉左下角的"长方体"，换上贴盆缘的弧形断层崖

- **病根**：旧断层崖是一条直线 `scarp()`，抬升侧**法向不衰减** ——
  西南侧整整一块 500 m 高、5.8 km 宽、20 km 长的**矩形板块**被原地抬起
  （掩码取证：覆盖 6.5% 图幅、全档满深），就是用户看到的「非常规整的长方体」。
- **重做**：照它本来要模仿的对象（临汾盆地：盆缘正断层**长在盆缘山梁内坡上**）
  重做 —— 断层迹线改成**与盆缘同心的圆弧**（西侧 ±55°），抬升块向外按
  dome 衰减（6 km 半宽，板块再也延伸不到图角），角向 smoothstep 收口。
  陡崖检测仍过：相位论证保证 (43,44) 一对格点跨满级 72.6°，实测崖 16 处、
  最大坡度 73.6°、suspect 0。

- 真机回归 **193/193**（G5 三条骨架数按新形状重测）；**红绿对照**：同一套新判据
  跑已发布的 v2.4.3 包 ⇒ **红 3 条，恰好全在 G5**（67/57、28/54、2/1 旧值）。

### 踩出来的坑（进 pitfalls-archive）

- `dome()` 吃到**负距离**时 `Math.pow(负数, 1.5)` = NaN，且 `0×NaN=NaN`
  挡不住、`Uint16Array` 落盘时 NaN→0、min/max 对 NaN **静默跳过** ——
  自检里表现为「平均 NaN」而判型照样通过。径向/有向参数必须先 clamp。
- 直线 `scarp()` 的抬升侧是**半无限带**：smoothstep 只管法向过渡带，
  不封法向边界 ⇒ "断层的抬升块"在渲染里变成矩形板块。

### 明确不做的

- 山地西侧断层崖（教学陡崖，本来就长在山坡上、用户没点名）**一个参数没动**；
- 丘陵的丘群、梁（RIBS）一字未动；
- 盆地的盆底/环山/放射冲沟/盆缘峰一字未动。


> **上一版基线：v2.4.2**（标签甩出去、用引线指回锚点）。
> v2.4.3 = **三维地形上不再写文字，只留颜色；山谷的线加白垫线**。
> 这一版有一半是**撤掉上一版刚加的东西** —— 引线标注上线一天就发现方向不对。

### ① 三维地形上不再有文字（撤掉 v2.4.2 的引线 + 标签）

你反馈的原话是「在图里的三维地形上面就不用再标注什么文字了，保留三维地形图里的颜色，
右下角有部位标注就可以了」。所以：

| | v2.4.2 | v2.4.3 |
| --- | --- | --- |
| 三维地形上的文字标签 | 12 条（"山峰 4200 m"、"陡崖 73°…"） | **0 条** |
| 引线 / 锚点圆点 | 12 条引线 + 12 个圆点 | **0**（锚点处只留彩色记号本身） |
| 五类彩色记号（▲◆▼ + 脊线 / 谷线） | 有 | **有（一个都没少）** |
| 右下角「部位标注」图例 | 有 | **有（五类 + 配色 + 检出数）** |

**为什么把图例单列一行**：文字撤掉之后，颜色就成了学生唯一能查的"说明书" ——
所以这一版的两半判据是**反向**的：既要验"文字真的没了"，也要验"颜色和图例真的还在"。
只验前半边是**可以被作弊通过的**：把整个标注层连颜色一起删掉，前半边照样全绿。

### ② 山谷的线加了一层白色垫线（你点名的那个"不明显"）

你反馈的原话是「山谷的标注有些许的不明显，在模板山地里面」。先把它量成数字再动手
（同机位逐类开关、与"全关"位图做逐像素差，得到每类记号真正画在屏幕上的面积）：

| 模板山地 | 斜视足迹 | 俯视足迹 | 最大通道差（与地形底色的对比度） |
| --- | --- | --- | --- |
| 山脊 | 359 px | 627 px | 196 |
| **山谷** | **104 px** | **110 px** | **118** ← 五类里最弱 |
| 鞍部 / 陡崖 / 山峰 | 72 / 219 / 122 px | 37 / 167 / 73 px | 116 / 219 / 185 |

两件事被排除掉了：
- **不是被地形挡住**：俯视（不可能被遮挡）才 110 px，斜视 104 px，比值 1.01。
- **不是颜色选错**：五类里山谷的蓝色本身没问题，是**线太细 + 底下就是浅绿等高线**。

而长度差是**地形结构**给的：山谷检出 63 格、山脊 76 格（数量接近），但骨架化出来的
折线总长 **46.2 格 vs 99.2 格**（山脊是一条完整脊线，山谷是树枝状散点）。
改长度要动模板判定与全部基线，所以这一版只改**显示层**：

- 山谷的线画**两遍**：**白色垫线**（粗）+ **蓝色谷线**（细）叠上去 —— 把它从等高线底色里"抠"出来。
- 两遍**画在不同深度上**（垫线低一点、蓝线高一点）。同深度会 z-fighting，蓝线被白线啃成虚线，比不加还糊。
- **山脊故意不加垫线**：脊线本来就有 196 的通道差（五类最高），没有看不清的问题。
  第一版"顺手都加上"了，放大 8 倍后发现脊线翻过棱线与棱线交接处会**露出白边、还散成白色碎片** ——
  纯副作用。只改被点名的那一条，顺带还让"带白边的蓝线 = 山谷"成了一种可区分的视觉特征。

改后（同机位、同一把尺子）：

| 模板山地 | v2.4.2 | v2.4.3 |
| --- | --- | --- |
| 山谷斜视足迹 | 104 px | **186 px**（+79%） |
| 山谷俯视足迹 | 110 px | **444 px**（+304%） |
| 山谷对比度（最大通道差） | 118 | **154**（+31%） |
| 山峰 / 山脊 / 鞍部 / 陡崖 | 122 / 359 / 72 / 219 px | **122 / 359 / 72 / 219 px（逐像素一致）** |

↳ 最后一行是这一版的**负向证据**：除山谷外四类一个像素都没动，
说明"山谷变明显"是靠给它自己补垫线换来的，**没有顺带动别人的观感**。

## v2.4.2 改了什么（2026-09-22）

> **上一版基线：v2.4.1**（五类地形部位一键标注 + 模板丘陵重做 + 垂直夸张自动匹配）。
> v2.4.2 = **标签从地形上挪开，改用引线指出**。

### ① 标注不再压在山上，改成「拉一条线指出去」

你反馈的原话是「现在的标注会直接挡住地形本身，建议拉出一条线来指出去然后再标注」。
问题确实存在，而且能量出来：模板山地打开全部标注时，12 条标签**两两重叠 77238 px²**
（"山峰 4200 m"直接压在"山峰 3051 m"上），因为它们全都贴在自己锚点的正上方。

现在每条标签由一条引线拉出去：

| | 记号 | 文字标签 |
| --- | --- | --- |
| 三维沙盘 | 锚点处留一个**小圆点**（颜色随部位） | 甩到旁边，中间用**引线**连回来 |
| 二维图纸 / 平面等高线图 | 记号形状不变（▲◆▼ 与脊谷线） | —— 这两处本来就只有记号，没有文字 |

引线画了两层：**白色垫线**（粗）+ **彩色引线**（细）。因为线要压在绿色地形、褐色台座、
灰色等高线上，单色线在深底上会糊掉。线头**钻进标签白底约 1.5px**（引线层压在标签之下），
看着是接实的；反过来写就会在接缝处留一道白缝。

改前改后（模板山地 12 条标签，同机位实测）：

| | v2.4.1 | v2.4.2 |
| --- | --- | --- |
| 标签两两重叠 | **77238 px²** | **0** |
| 标签中心到锚点距离 | 固定 **17 px**（几乎贴着） | **87 ~ 177 px** |

### ② 甩的方向怎么定：三个坑，都是真机回归里量出来的

甩出去不是"随便挑个方向"，三条规则按优先级：

1. **方向 = 从"这一批锚点的质心"指向该锚点**（径向向外）。用质心而不是舞台中心：
   质心贴着地形本体，方向天然是"从地形往外"，而且随相机**连续**变化，转视角时标签不会跳位。
2. **径向会被舞台边挤回来时换方向**。锚点贴在画布角上时，径向指向屏幕外，标签被夹回
   锚点头上 —— **正好把锚点盖住**。实测四个角 4/4 全中。所以方向是试出来的：
   从径向起按 20° 一档往两侧转，取第一个"标签不压住锚点"的方向；角落里要转到 150°~180°。
3. **同样能让开时取引线更短的那个**。这一条是**看了真机截图才发现的**：第一版按
   "先试到哪个方向就用哪个"，结果 7 处陡崖的标签被一路推到舞台顶边，引线横跨半个屏幕。
   改成"同分取最短"后，最长引线从 251px 收到 137px。

第 2、3 条只影响"贴边的锚点"与"挤在一起的锚点"（模板山地那 7 处陡崖在同一条 380 m 断层上），
普通样本一个数字都没动。

### ③ 顺带补了一处防御：锚点坐标不是数字时不要硬画

真机回归里我的脚本把相机坐标（数组）当成对象用，算出 `NaN` 传了进来 —— `NaN` 与任何数比较
都是 false，于是"越界判定"全过、标签被堆到舞台中心，**而屏幕上只是"标注没跟着地形走"**。
现在非有限数的锚点一律按"不可见"处理（标签、引线、圆点全不画）。

### 验证

- **数据层测试 11 套件 / 1100 项全绿**，其中新增 `CALLOUT CHECK 44 项`（引线布局的几何单测：
  输入边界 / 单标签几何 / 多标签避让 / 自证 / 稳定性五节）。
- **真机渲染回归 211 项全绿**（新增 H 节 38 项：距离 / 包含 / 重叠 / 界内 / 引线端点 / 多机位 / 换样本）。
  **反向跑同一份脚本的 v2.4.1 产物 ⇒ 红 19 条，全部落在 H 节** ——
  比"修后全绿"更有力：新判据咬得住旧代码，且没有顺带咬到别的。
- **"这版只改了显示层"有一张逐像素的硬证据**：同一机位、标注全关时，
  v2.4.1 与 v2.4.2 的三维舞台位图 **767040 个像素全部相同，0 个变化** ——
  地形渲染一个像素都没动。

### 特意没做的事

- **没做全局最优摆放**。标签避让是"逐个放置 + 贪心"，不追求最优 ——
  最优摆放在计算上是 NP 的，而且这里每帧要重算（相机会被一直转）。
- **没给标签加自动缩进 / 合并**。同一条断层上 7 处陡崖仍然会标 7 条（各带自己的海拔与坡度），
  这是有意的：那本来就是 7 个不同的点，合并成一条反而丢信息。
- **没动检测与读数**。本版一个字没改几何判据、骨架化、垂直夸张。

## v2.4.1 改了什么（2026-09-22）

> **上一版基线：v2.4.0**（改名「口袋地形」+ 新增三个模板地形）。
> v2.4.1 = **五类地形部位一键标注** + **模板丘陵重做** + **垂直夸张自动匹配**。

### ① 五类地形部位可以一键标到图上了

侧栏多了一组「**地形部位标注**」，五枚按钮：山峰 / 山脊 / 山谷 / 鞍部 / 陡崖。
点一下，记号**同时**出现在三处 —— **三维沙盘、二维投影图纸、平面等高线图**。

| 部位 | 图上的记号 |
| --- | --- |
| 山峰 | ▲ 实心三角（带海拔） |
| 鞍部 | ◆ 菱形（带"下凹多少米"） |
| 陡崖 | ▼ 倒三角（带坡度与落差） |
| 山脊 / 山谷 | **线**（不是点） |

- **不是画上去的，是检出**：五类部位来自 DEM 的几何判据（山峰 = 非极大抑制 +
  相对起伏门槛；山脊/山谷 = TPI 高分位/低分位；陡崖 = 坡度 ≥ 65° 且单格落差有上限；
  鞍部 = 两峰之间那个低处，且有跨度与下凹幅度门槛）。按钮上直接写着本样本的**检出数**。
- **灰化判据不是"检出数 > 0"**，而是"这一类在本样本上**画得出来**"。
  例：川中丘陵检出 1 处山脊，但那一格是孤立点，骨架化之后一条线都没有 ——
  按钮亮着却什么都画不出来，比灰掉更让人困惑。灰掉时 `title` 里写明理由
  （"本样本检不出可连成线的位置（检出 N 处，太零散）"），**不静默灰**。
- **「全部标注」/「清空」**两枚快捷按钮；组标题显示「N/5 类」。

#### 脊线 / 谷线是**骨架化**的结果 —— 这件事在界面上写明了

山脊/山谷不是一个个孤立的点，而是**成串的格子**。直接把这些格子画出来会得到一条
"毛茸茸的带子"（宽度随坡度变），学生看不出"脊在哪"。所以做了三步：
闭运算补断点 → **Zhang-Suen 细化**成 1 格宽的中心线 → 剪掉短于 5 格的毛刺、把断口 ≤ 12 格的线接起来。

⚠️ **这带来一个必须说清楚的口径问题**：这条线是**细化**出来的，不是"检出的脊格本身"。
所以图例小字与侧栏提示里都写着：

> 脊线与谷线是**骨架化**的结果 —— 由检测出的格子（76 个脊格 / 63 个谷格）细化成线，
> 不是人工画的分水线；所以它表示"检测到的脊 / 谷在哪一段"，不等于严格的流域分界。

教学材料里这件事不能含糊：老师指着一条线说"这是山脊"，得知道它是**怎么来的**。

### ② 模板丘陵重做：从"一块缓板"改成 62 座小丘

上一版的模板丘陵是"20 km 平板上扣 6 个圆包 + 三道长波起伏"，量出来局部高差中位数
只有 **88 m** —— 视觉上就是一块缓板。用户原话：「**太草率了，看得感觉非常不像是丘陵，
丘陵至少还是要有很多座比较明显的山**」。

这一版整个 `buildHill` 重写：**9×9 格点（间距 28 格）上带抖动的密集小丘群，共 81 座**，
每座的半径与高度各按 `hash01` 抖动（仍然**不含随机数**，同参数逐字节可复现）。

| 量什么 | v2.4.0 | v2.4.1 |
| --- | --- | --- |
| 丘顶（突出度 ≥ 25 m、环半径 12 格） | 16 座 | **62 座** |
| 丘顶突出度中位数（"明显"） | 253 m | 126 m |
| 丘顶**最近邻间距**中位数（"分得开"） | 566 m | **1886 m** |
| 局部高差中位数（判 hill 的那个量） | 88 m | **139 m** |
| 高程范围 | 146–596 m | 165–518 m |

判据是**成对**的，不能只看个数：光堆个数会让丘糊成一坨（"很多座"变成"一片疙瘩"），
所以同时卡**间距 ≥ 800 m** 与**局部高差 ≥ 110 m**。图幅仍是 20 km，位置与五个部位照常检出。

> **⚠️ 别把"62 座"和界面上的「山峰 6+」当成一回事。**
> 丘顶 62 座是用"突出度 ≥ 25 m"的**形状判据**量的；界面上的山峰记号有
> `PEAK_MAX_COUNT = 6` 的**展示封顶**（鞍部是两两配对，峰多了组合爆炸且没教学意义）。
> 拿它量"有多少座丘"会永远得到 6 —— `template.test.cjs` 里专门写了这一条。

部位检出跟着变（形状变了，检出当然跟着变）：脊 72 → **19**、谷 43 → **46**、
鞍 4 → **2**、峰 6（本来就是封顶值，看不出变化）、崖仍是 **0**。

### ③ 垂直夸张改成"坡度取向"，换样本自动给推荐值

以前垂直夸张固定 ×1，平缓地形（华北平原、模板丘陵）起伏被压得看不出来。
这一版按**该样本的坡度**自动推荐：

```
倍数 = tan(25°) / tan(第 90 百分位坡度)     然后钳到 [1, 20]
```

**为什么是"把典型陡坡抬到 25°"而不是别的**：目标是"让起伏看得清，又不让山变成假的"。
对真实山地，它本来就陡 ⇒ 推荐值就是 **×1**（不该再抬，再抬山形就失真、
垂直地带性的教学对比整个废掉）；对平原/丘陵/高原，抬高到 25° 才看得见起伏。

实测（默认值 = 推荐值）：

| 样本 | 推荐倍数 | | 样本 | 推荐倍数 |
| --- | --- | --- | --- | --- |
| 模板山地 | **1.000** | | 贡嘎山 / 珠峰 / 梅里 / 太白山 | **1.000** |
| 模板丘陵 | 2.140 | | 华北平原 | **20.000**（上限） |
| 模板盆地 | 1.840 | | 内蒙古高原 | 5.980 |
| 川中丘陵 | 2.420 | | 临汾盆地 | 2.050 |

- 界面给出「自动 ×N」档 + 一个「**自动**」小标 —— 让老师知道这个数是**系统给的**，
  不是上一版留下的旧值。手动拖一下滑块，小标就消失（表示"你改过了"）。
- 代价两条：`EXAGGERATION_MAX` **2.0 → 20**；滑块改成**对数刻度**
  （线性刻度下 0.5→2 只占 7.7% 行程，而 2→20 占 90%，手感完全不对）。
- **夸张倍数不进海拔** —— 它只乘渲染顶点的 Y，所有读数（海拔、等高线、带谱边界、
  剖面）都不受影响。这条从 v1.x 起就是硬约定。

### ④ 顺带修掉两处"零报错"的自相矛盾

都是这一版新增标注功能时**被新断言抓出来的**，不是猜测：

1. **舞台角标把模板也写成「真实 DEM」**。模板山地的舞台角标印着
   「真实 DEM 753–4200 m」，而同一个屏幕上侧栏徽标写着「示意地形」、
   页脚写着「解析函数生成」—— 三处自相矛盾却没有任何报错。
   模板从 v2.4.0 起就是**默认样本**，所以这是打开游戏第一眼就会看到的矛盾。
   现在分档：模板「解析生成 753–4200 m」/ 真实「真实 DEM …」。
2. **"图例说标了、图上什么都没有"**。`showParts` 是**用户的意图**，它跨样本保留 ——
   在模板山地上勾了「陡崖」，切到模板丘陵（一处陡崖都检不出）之后，那个 id 还留在数组里。
   于是：图例列着「陡崖 0 处」、按钮**灰掉却还是选中态**、组标题写「5/5 类」而实际只画出 4 类。
   现在显示层统一按"**有效选中** = 被选中 ∩ 画得出来"来算；
   **刻意不改 `showParts` 本身** —— 用户切回模板山地时，陡崖应当自己回来，而不是被悄悄丢掉。

### ⑤ 底层：修好骨架化自己的两个缺陷

这一版的脊/谷线是新写的 `skeleton.ts` 产出的。写完先做**独立测量**（而不是信注释），
量出两处**静默**错误 —— 两处都和自己的注释说的不一样：

- **`erode` 会把贴着图幅边缘的脊整条删掉**。"图幅外视为背景"的写法在腐蚀时
  变成"图幅外视为**前景**"，于是紧贴左边框的一道脊线**整条消失**（实测：满场
  腐蚀后 3364 格 vs 应有的 4096 格；贴边的那条脊 8 列全是 0）。改成
  腐蚀 = 对**补集**做膨胀，语义自然就对了（补集在图幅外是背景 ⇒ 反过来就是前景）。
- **`prune` 每次都会剩 2 格毛刺**。判"走到交叉口了"用的是**下一个格子**的度数，
  而 8 邻接里紧挨交叉口的那个格子自己就是 3~4 度 ⇒ 永远提前刹车。
  改成只数**没走过的**邻居。实测同一组毛刺（长度 1~7）剩下的格子：
  旧 `0,0,1,2,3,4,0` → 新 `1,0,0,0,0,6,7`（长度 ≥5 的本来就该留）。

两处修复**只**影响"贴边的脊"与"毛刺短桩"，模板地形两者都没有 ⇒
模板的骨架格数/线数**一个都没动**（回归里专门卡了这条，作为"改动波及面"的排他性证据）。

### ① 游戏改名叫「口袋地形」

原名「真实地形山地 · 垂直地带性」。新名字少一个"山"字不是好听 ——
原名把**丘陵、盆地**挡在门外了，而这一版恰恰新增了这两种。

⚠️ **`gameCode` 没变，还是 `mountain_zones`**。所以老师手里的课程链接、邀请码、

`manifest.json` 的 `name`、两个 HTML 的 `<title>`、封面图横幅、游戏内标题、本文件与 README。

### ② 新增三个「模板地形」：模板山地 / 模板丘陵 / 模板盆地

**为什么加。** 真实 DEM 很好，但对刚上初中的学生，一座真山是"一团复杂的皱褶"——
要在上面指出"这里是鞍部、那里是陡崖"，他先得学会忽略大量细节。
模板地形是**为看清教科书那五个部位而专门构造的山**：山体填满图幅、特征尺度过关、
每个部位都在学生一眼扫到的地方。真实地形**全部保留**（8 个一个没删），
老师按学生的程度自己选。

| 样本 | 类型 | 图幅 | 海拔 | 局部起伏 | 检出的五类部位 |
| --- | --- | --- | --- | --- | --- |
| **模板山地** | 山地 | 20 km | 753–4200 m | 500 m | 峰 3 · 脊 76 · 谷 63 · 鞍 2 · **崖 7** |
| **模板丘陵** | 丘陵 | 20 km | 146–596 m | 88 m | 峰 6 · 脊 72 · 谷 43 · 鞍 4 · 崖 **0** |
| **模板盆地** | 盆地 | 40 km | 400–1949 m | 797 m | 峰 6 · 脊 43 · 谷 50 · 鞍 1 · 崖 5 |

- **模板山地把五类部位一次摆齐**：两座主峰夹一个鞍部（峰顶间距 82.2 格，落在鞍部的
  最大跨度阈值 90 格之内，所以"两峰之间那个低处"确实会被认成鞍部）；两条山脊从主峰
  甩出去；山谷顺着坡切下来；陡崖是一道 380 m 的直立断层（水平位置刻意卡在
  `x = 72.5` 两个采样点之间，见下"台阶的相位"）。
- **模板丘陵没有陡崖，而且这是对的**：丘陵最陡处实测 **53.5°**，而陡崖门槛是 **65°**。
  想让它出陡崖，得把相对高度推到 300 m 以上 —— 那就不叫丘陵了。
  所以"丘陵不含陡崖"是**地形本身的属性**，不是这一版偷懒没做。
- **模板盆地不是"一个坑"**：盆底是一片平坦底盘，四周一圈山地（外环比中心高 788 m，
  8 个方位全部成立）。学生能一眼看出"四周高、中间低"，也就看出"盆地"这个类型
  和"鞍部"这个部位不是一回事。

三个模板都是**解析函数生成**（圆锥 / 圆顶 / 高斯脊叠加），**不含任何随机数** ——
同参数跑两遍必然逐字节一致。这不是洁癖：正因为可复现，我们才能把生成结果的
sha256 钉成"只读契约"，形状被谁手改一下立刻变红（见「验证」）。

### ③ 入口：同一个选择器分两组，模板排在前面

打开游戏**默认落在「模板山地」**（先认部位、再上真山，符合教学顺序）。
模板那一组带一句提示：*不是真实地点，是为了看清五个部位画出来的样板*。
真实地形按五类类型标签筛选，分组完全不变。

### ④ 模板地形不画中国地图，换成一张说明卡

模板是示意地形，**没有省份可标**。硬套一张中国地图 + 一个红点，等于告诉学生
"这座山在四川"——**是错的**。所以这一栏对模板换成说明卡：这张图为什么长这样 /
五类部位在这张图上分别在哪 / 它和下面真实地形的分工。
地理位置栏对模板显示「示意地形」，真实地形照旧显示省份与到省几何重心的距离。

纬度 / 季节 / 海拔偏移 / 垂直夸张**一个都没锁**。模板地形同样能讲垂直地带性：
把模板山地（峰顶 4200 m）抬到雪线之上，带谱照样收紧、径流照样归零。
"简化的是地形形状，不是模型"。

角标是为了让人**一眼分清哪些是编的、哪些是真的** —— 教学材料里这件事不能含糊。

### 特意没做的事

- **没删任何真实地形样本**。8 个全在，包括只有它是 60 km 图幅的临汾盆地。
- **没改 `gameCode`、没改 `requiresRoster`**（仍是 `false`，打开即教学）。
- **没给模板降精度**。模板和真实样本一样是 256×256 网格、同样走
  `extractContour` 画等高线、同样能拉剖面 —— "简化"只发生在**形状**上。
- **没把模板做成"玩具模式"隔离出去**（不加"演示专用"开关、不隐藏参数）——
  一旦隔离，老师就不敢在讲正课的时候用它了。

### 一个被推翻的旧结论（记在这里，免得下次又推一遍）

v2.2.0 的文档里我写过一句**"丘陵没有山脊"**。这一版做模板丘陵时按它构图，
结果脊点占比 **0.00%**、谷点 0.07%，测试直接红。

量了一遍才发现：那句话量的是**我自己的构图**（几个圆顶摆在平板上），**不是丘陵本身**。
补上两道窄梁（`RIBS`）之后，脊点从 0 变成 **72 个**，与谷的 43 个同量级。

**教训**：把"某个地形类型有没有某个部位"写成结论时，必须问一句
"我这是量的地形，还是量的我画的那张图？"

### 一个静默陷阱（值得别的游戏也看一眼）

给模板填的地理坐标是**占位值 30°N / 105°E**。这个点是**成都附近，在中国国境线以内**——
于是"这个坐标在中国境内吗"这类校验**全部通过**，界面上什么错都不会报。

真正的危险是另一条链路：`locationByTag(tag)` 在查不到时会**静默回落**到
`SAMPLE_LOCATIONS[0]`（贡嘎山 / 四川省）。只要有人忘了走 `isTemplate` 分支，
模板山地就会一本正经地显示"四川省"、并在中国地图上点一个红点 ——
**数据错了、位置偏了，屏幕上一点异常都没有**。

所以 `locmap.test.cjs` 新增了第 6 节，把这条**当成契约钉住**：
模板地形不在 `locations.ts` 里、lat/lon 必须是占位值、`locationByTag` 的回落是哨兵值。
下一次谁动这块，测试会先红。

## v2.3.0 改了什么（2026-09-22）· 补记

> 这一版在本文件建立之前已发布，据 README 的同期记录补记。

- **修好"完全看不到二维图纸"**：图纸与沙盘的间隙从 0.05 跨度提到 **0.62**。
  原来图纸 **94% 被沙盘自己压住**，屏幕上只剩最近那个角露出 6%。
  几何门槛是 `gap ≥ tan(俯角) × 1.41 ≈ 0.54` —— 原值和门槛差一个数量级，
  而且**不报错、不警告**，八张截图里那张纸若隐若现，很容易被当成"相机角度不对"糊过去。
- **间隙 / 俯角 / 取景收进 `layout.ts`**（纯数学、不依赖 three.js）：渲染两侧**引用**、
  测试**验算**，一份口径。根因就是这两半参数分居 `terrain.ts` 与 `view3d.ts`，
  **谁也不知道对方**，没人会发现它们必须一起改。
- **两个显示开关各自独立**：可以只留沙盘、也可以只留图纸。只留图纸时
  **拾取平面从地表切到纸面**，仍能在平面图上画剖面 —— 否则学生关掉沙盘后
  鼠标点什么都没反应，而没有任何提示。
- 相机取景改成按装配体包围盒**拟合**（解精确不等式，不再用正交近似——
  后者实测会把近侧的角顶出画面 26%）。
- 图纸可见率实测 **5.7% → 100%**。
