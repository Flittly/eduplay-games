## v2.5.3 改了什么（2026-10-05）—— 「自己标部位」区块的 UI 与全站统一

用户反馈：「自己标部位」这个地方的 UI 设计风格没有和项目的 UI 统一，**按钮样式不是现在这种**，
**提示的这些话所在的框也不是**（举例：「正在标山峰：在沙盘上点一下落标注…」这句所在的框）。

**地形数据逐字未动**（三个模板的 b64 指纹与 v2.5.2 完全相同，DEM 读数全部不变）——
本版只改界面样式与两处文案。

### 实测出来的四处破例

先用 `getComputedStyle` 把这一块的每个元素量了一遍，与全站基准（`.mz-chip` / `.mz-tplcard` /
`.mz-notice` / `.mz-dex-card`）逐项比：

| 元素 | 改前 | 全站基准 | 改后 |
|---|---|---|---|
| 提示框圆角 | `0 4px 4px 0`（**全站唯一非零**） | `0` | `0` |
| 提示框左条 | `3px` | `4px`（`.mz-notice`/`.mz-pending`） | `4px` |
| 提示框字重 | `400`（与旁边正文**一模一样**） | 比正文重 | `700` |
| 行内小按钮边框 | `1px solid rgb(138,124,105)` | `2px solid` 实墨 | `2px solid` 实墨 |
| 行内小按钮圆角 | `3px` | `0` | `0` |
| 行内小按钮底色 | `transparent`（纸上等于看不见按钮） | `var(--paper-3)` | `rgb(250,245,234)` |

（「退出」和「删除本机这份标注」这两个按钮就是「行内小按钮」。）

### 另外三处不是样式表里的问题

- **选中态色条写在了 TSX 内联 style 里**（`boxShadow: "inset 0 -3px 0 <部位色>"`），
  不在样式表 ⇒ 改配色要去翻 `.tsx`，也躲过了所有统一规则。已收进
  `.mz-chip.is-part.is-on`，JSX 只喂 `--part-color`。
  ⚠ **顺带发现两处内联**：「地形部位标注」和「自己标部位」两组**共用同一个
  `mz-chip.is-part` class 却各写了一份内联**，而且规格不一样（`-3px` vs `-4px`）⇒
  互相覆盖。改成同一个样式表规则后两组自动一致。
- **两句文案把 Markdown 的 `**` 直接写进了 JSX**（`标注**本次有效**` /
  `关着时画的是**程序检出**的结果`），渲染出来是**字面的星号**而不是加粗。已改成 `<b>`。
- 部位按钮选中时，色点在墨底上没有描边会糊掉 ⇒ 加了一圈纸色描边 + 1px 墨圈。

### 验证

- `test:data` **1069 项 0 失败**（本版不该碰数据层，正好确认没碰坏）
- 真机回归 **67 项 × DPR 1 与 1.25 全 0 失败**（59 项 + 新增 8 条 I8 风格判据）
- **新判据反向在 v2.5.2 产物上 8 条全红**，每条都带具体数值理由
- 打包指纹正向 ✔ 绿；**反向 `--audit` v2.5.2 包 ✔ 红，恰好缺 2 条新 CSS 指纹**，
  且旧包里仍能翻到那句内联 `boxShadow`（已登记成删除型指纹 `GONE_JS`）

### 这批判据是怎么写的（留给下一个人）

风格判据的关键是**量计算样式**而不是读 CSS 源码，而且口径是「**与全站基准同规格**」
而不是「等于某个具体值」：

- `var(--x)` 要在计算值里才解析成颜色，比字符串毫无意义；
- 内联 `box-shadow` 在 CSS 源码里**根本不存在**，只 grep 样式表会得出「色条还在」的错觉；
- **不能写死像素值** —— DPR=1.25 时浏览器把 2px 算成 1.6px、4px 算成 3.2px，
  写死会在 1.25 那一遍假红（实测踩过）。要比就比彼此。
- **参照物必须与被测物同族且必定取得到**。这一条我换错了三次：
  先参照「拒绝提示」（当前样本没有 ⇒ 取不到）、再参照图鉴卡（边框 1.5px）、最后参照
  模板卡（2px 卡片边框，而旧的 3px 本来就「不小于」2px —— **方向反了**）。
  提示条的左条只能跟**另一条提示条**比，且运行时取不到就从站点 CSS 文件里读。
- **断言「某段文字不存在」时必须先把那段渲染出来**：那两句带星号的文案分处
  两个条件分支，默认只显示一条 ⇒ 只扫默认状态是**假绿**。源码层扫描在 Node 侧做
  （送进页面的 `async` 表达式会被 `JSON.stringify(Promise)` 变成 `{}`）。

## v2.5.2 改了什么（2026-10-05）—— 丘陵「减量增大」+ 丘陵与盆地加坡面噪声

用户要求（两条）：「模板丘陵和模板盆地也应该加上这类似的噪音，显得更加的真实」、
「丘陵的数量可以减少，但是丘陵的体积需要增大」。

**模板山地逐字未变**（b64 指纹与 v2.5.1 完全相同）。

### 丘陵：81 座 → 36 座，丘高 110 → 150 m、半径 7.0 → 11.0 格

| 参数 | v2.5.1 | v2.5.2 |
| --- | ---: | ---: |
| `NL`（每边格数 ⇒ 丘数 = NL²） | 9 → 81 座 | **6 → 36 座** |
| `PITCH`（格距） | 28 | **44** |
| `HILL_R_CELLS`（半径） | 7.0 | **11.0** |
| `HILL_H`（丘高） | 110 | **150** |
| 坡面噪声 | 无（三组平面波 7/6/5 m） | **45 m / 1400 m / 4 倍频** |

**"体积增大"的有效旋钮是丘高，不是半径。** 实测 `hillR` 从 7 放大到 13，
局部高差只从 141 动到 143 —— 因为 `dome` 在半径处归零，放大 R 只会让
**相邻丘互相重叠、坡面反而变缓**。真正给"体积感"的是 `hillH`。

### ⚠ 丘陵离判型上限只剩 21 m（本模板最紧的约束）

局部高差 **155 → 179 m**，而 `LOCAL_RELIEF_MOUNTAIN = 200`（超过就判型从
`hill` 翻成 `mountain`，「丘陵」这个模板就不成立）。实测 `hillH` 升到 170 就到 190 m。
**改任何丘陵参数之前先量它。**

### 盆地：加坡面噪声 120 m / 2000 m（骨架未动）

| 项 | v2.5.1 | v2.5.2 |
| --- | ---: | ---: |
| 判型 / 高程 | basin · 400~1867 m | **basin · 317~1926 m** |
| 峰 / 脊 / 谷 / 鞍 / **崖** | 3 / 184 / 185 / 2 / **16** | 4 / 182 / 176 / 2 / **16（未断）** |

最担心的是噪声打断盆缘断层崖（靠 `drop = 500 m` 的 `smoothstep × dome` 陡坎撑着），
**实测 15 组扫参全部 16 处不变** —— 120 m 噪声啃不动它。

### 振幅与波长都按各自图幅等比缩放，没照抄山地的 450 m

山地起伏 1283 m、噪声 450 是 **35%**；丘陵起伏只有 ~150 m、盆地 687 m。
丘陵取 45 m（≈30%），**照抄 450 会把坡面啃碎、把判型顶过 200 m**。
波长也不能照抄：盆地是 40 km 图幅，实测 800 m 波长时脊 184→338、谷 185→307
（几乎翻倍，教的部位变杂）—— 只能用 ≥2000 m。

### 三条硬判据全守住（实测，非目测）

| 模板 | 判据 | 余量 |
| --- | --- | --- |
| 丘陵 | 判型不能翻成山地（< 200 m） | 179 m，**剩 21 m** |
| 丘陵 | 四类部位（峰/脊/谷/鞍）齐全、崖恒 0 | 6/36/58/4/0 ✔ |
| 盆地 | 判型仍 `basin`（边缘比中心 ≥120 m、8 方位中 ≥6） | 751 m、8/8 ✔ |
| 盆地 | **陡崖不能断**（65°~80° + 单格跨 ≥2 条 100 m 等高线） | **16 处未变** ✔ |

### 顺带修掉一个隐患：肋/沟的格位索引写死了 `NL = 9`

`ribBetween(hillAt(6,6), …)` 与 `corridorJ(7)` 都是硬编码。`NL` 一降到 6：
`hillAt(6,6)` **越界返回 `undefined`** ⇒ `ribBetween` 读 `A.i` 直接抛
（还算好，会崩）；更隐蔽的是 `corridorJ(7)` —— 它只是算术，**不报错**，
会把第三条冲沟放到 `17 + 7·44 + 22 = 347 > 255` 即**图幅之外**，沟白画。
现在全部写成 `NL − k` 形式。

### 验证

- `test:data` **1069 项 0 失败**（骨架摘要 `ee081f157dd21d78…`、
  b64 指纹 `fc24dced…` / `9d3eceb9…` 均重钉）
- 真机回归 **59 项 × DPR 1 与 1.25 全 0 失败**
- 打包指纹：正向 v2.5.2 包 ✔ 绿；**反向 `--audit` v2.5.1 包 ✔ 红，恰好缺 4 条**
  （丘陵与盆地各 2 条高程串）

## v2.5.1 改了什么（2026-10-05）—— 模板山地「坡面不再像塑料」

这一版**只动模板山地表面的噪声**。骨架（两座山、两个峰、山体半径、垄高）与
丘陵 / 盆地 / 四座真实山 / 华北平原 / 内蒙古高原**一行未改**。

起因是用户看图后的一句：「**但是这两座山也太园了吧**」。

### ① 先量后改：「圆」是可以量出来的，而且差得很远

不靠眼睛判断，把「圆」拆成三个可量化的维度，与四座真实山**同口径**对比：

| 样本 | ① 峰顶 300 m 等高线圆度 | ② 四方位剖面抖动度 | ③ 300 m 脊线格数 |
| --- | ---: | ---: | ---: |
| **tpl_mountain（本版改前）** | **0.504** | **0.035** | 1 |
| gongga 贡嘎 | 0.288 | 0.822 | 3638 |
| everest 珠峰 | 0.291 | 0.792 | 3760 |
| meili 梅里 | 0.303 | 1.121 | 3549 |
| taibai 太白 | 0.150 | 1.178 | 3659 |

* **圆度** = `4π·面积 / 周长²`（正圆 = 1，越碎越接近 0）；
* **抖动度** = 四方位剖线的二阶差分绝对值之和 / 总落差（平滑曲面 ≈ 0.01~0.06，
  真山有冲沟 > 0.79）。

结论：**模板的等高线比真山圆近一倍，坡面比真山平滑 25 倍，山脊线少了三个数量级。**

### ② 四条修法全部实测失败（这一版真正的价值在失败记录）

| 方案 | 结果 | 死因 |
| --- | --- | --- |
| 噪声振幅放大（210 → 1500 m） | 圆度 0.46 → **0.28** ✔ 但**连通块 117 块、谷底 −144 m** | 山被撕碎，不是山了 |
| `shoulder`（圆肩 + 幂锥外坡，`rt1400`） | 圆度 **0.218** ✔ 抖动 **0.731** ✔ | **机器检出峰 2 → 6**（多出 4 个在主峰周围十几格内，只低 100~240 m） |
| `shoulder` + 峰顶锥放大到 3600 | **16/16 全败** | 锥盖住峰顶圈 ⇒ 坡上检出次级峰、脊线 436~908 |
| 各向异性椭圆穹顶（`kx` 扫参） | 圆度 0.45~0.52 几乎不动 | `kx ≥ 1.15` 时山体**重新连成 1 块** |
| `TILT` 振幅放大八倍（0.147 → 1.2） | 圆度 0.497 → **0.503** | 线性项对任何等高线都只是**平移**，形状压根不变 |

两条几何事实（已写进 `gen_templates.cjs` 注释）：

1. `dome(d, R, p)` 是**余弦旋转曲面** ⇒ 它的任何水平截面**必然是正圆**；
   纯骨架在峰顶往下 100/300/500/800/1200/1800/2500 m 处圆度是
   0.476 / 0.460 / 0.547 / 0.594 / 0.639 / 0.689 / **0.765**，越往下越圆。
   ⇒ 噪声只能在圆周上啃锯齿，是「把圆弄脏」不是「把山弄自然」。
2. **加线性项改不了等高线形状。** 要破圆必须换峰顶锥的形状函数。

顺带查出一个存在很久的**死代码**：`TILT` 的坐标 `{i:110,j:119}` / `{i:146,j:137}`
是 **v2.4.7 的旧峰位**，峰位搬到 (77,77)/(179,179) 后
`PEAKS.find((t) => t.i === p.i && t.j === p.j)` 恒不匹配 ⇒
**自 v2.4.8 起一行都没生效过**。本版**不修**（它对等高线形状毫无影响，
修好也只是整体倾斜，与破圆无关）。

### ③ 最终采用：只加噪声，并保住「只标 2 个峰」

用户选定的方向是「**加噪声破圆，骨架不动**」，但坚持「**只标 2 个峰**」。
这两条是**数学冲突**的：噪声打大就会在峰顶周围打出次级极大。

扫 128 组噪声参数（振幅 200~850 × 波长 1400~3000 m × `maskScale` 0/0.5/0.75/0.9），
**只有 2 组过**，最终取第一组：

| 参数 | v2.5.0 | **v2.5.1** |
| --- | ---: | ---: |
| 振幅 `amp` | 210 m | **450 m**（×2.1） |
| 波长 `1/inv` | 3 000 m | **1 400 m** |
| 倍频 `oct` | 4 | 4（不变） |
| `maskScale` | 0.75 | 0.75（不变） |
| `seed` | 3 | 3（不变） |

**`maskScale = 0.75` 就是「只标 2 峰」的守护者**：它在两峰**连线**上把噪声压掉，
峰顶那一圈因此打不出次级极大。同参数去掉 mask ⇒ **峰 6**。
（这条「轴」来自 `RIDGE.a → RIDGE.b`；v2.5.0 的垄已归零、两峰恰好都在对角线上，
所以它现在保护的是「两峰连线」，与山脊无关。）

## v2.5.0 改了什么（2026-10-05）—— 模板山地「真的变成两座独立的山」+ 峰判据换基准

这一版只动**模板山地**的形状和**峰判据**。丘陵、盆地、四座真实山、华北平原、
内蒙古高原的读数除峰判据带来的修正外都不变。

### ① 先说清楚 v2.4.x 到底错在哪

用户提的问题是「为什么两座山还是连接在一块的」。

先量后查，结论是**归因错了**：v2.4.9 的注释把"连接"算在连接垄 `RIDGE` 头上，
实测下来垄只是加重症状，**病根是两个山体本身就重叠**：

| 量 | v2.4.9 实测 |
| --- | --- |
| 山体半径 | 14 000 m = **178 格** |
| 图幅 | 只有 256 格 |
| 两峰中心距上限 | 120 格 |
| **山体掩膜连通块** | **1 个**（31 904 格，占 48.7%） |

两个 R=178 格的圆顶放在 256 格的图幅里，**必然重叠成一个椭圆包**。
所以削垄、加宽垄、把垄高从 2000 压到 0，全都只是在这个椭圆上修修补补 ——
渲染出来永远是一个整体。v2.4.7~v2.4.9 三版都在这上面绕。

顺带纠正 v2.4.x 注释里的一个**错误解释**。当时写的是"削垄等于削峰"，
实测机制是另一回事：

| 垄高 | 峰顶与 ±12 格邻域落差 | 旧峰判据门槛 | 峰数 |
| ---: | ---: | ---: | ---: |
| 2000 | 1578 m | 1233 m | 2 |
| 1200 | 1017 m | 1057 m | **0** |
| 800 | 736 m | 969 m | **0** |
| 0 | 335 m | 811 m | **0** |

垄是旧判据下峰顶突出度的**主要来源**。换成坡度判据之后垄就能归零。

### ② 改法一：构图 —— 两座山真的分开

| 参数 | v2.4.9 | v2.5.0 |
| --- | ---: | ---: |
| 山体半径 | 14 000 m | **6 500 m** |

⚠ 高程上限从 6731 掉到 4879 是**预期**：山体小了一圈，垄也不再贡献 2000 m。
不是"山变矮了"，是"山不再靠垄撑着了"。

### ③ 改法二：峰判据换基准（这一条影响所有样本）

旧判据拿**全图高差**当门槛的参照系：

```text
drop >= max(45, 0.22 × 全图高差)
```

`drop` 量的是「峰顶相对**自己邻域**最低点的落差」，门槛却参照「**全图**多高」。
两座高度悬殊的山放在同一张图上时，矮山永远不合格：

- 主峰落差 1317 m，过门槛；
- 副峰落差 652 m，被主峰撑高的门槛卡掉。

新判据改用**峰顶自身的平均坡度**，与"全图多高、别座山多高"完全无关：

```text
drop >= tan(θ) × reliefRadius × cellM
```

其中 `reliefRadius = 18 格`（约 ±1.4 km），`drop / (reliefRadius × cellM)` 就是峰顶邻域的
平均坡度。原来的 12 格太小 —— 独立小山在圈内掉不下去，实测邻域越大越容易检出峰。

θ 不能写死：固定 22° 会让模板丘陵（起伏 313 m）与模板盆地（40 km 图幅）
双双 0 峰。改成随地形起伏线性缩放：

```text
θ = 8° + (24° − 8°) × min(1, relief / 5000)
```

物理含义：高山里的峰本来就可以比丘陵上的丘更陡。

`cellM` 必须按**真实图幅**算，不能硬编码 `20000/255` —— 否则 40 km 图幅的模板盆地
门槛会被算高一倍。已由 `landParts(h, n, spanM)` 用自己的 `spanM` 传下去。

### ② 为什么"两边的山"源码里明明差 238 m，落盘却只差 27 m

这是这一版最值得说的一处：**`PEAKS[].H` 这个旋钮在双大圆顶架构下几乎是废的**。

两座山的山体半径分别是 11.2 km 与 10.4 km，中心距只有 3.1 km —— 也就是
**0.28 个半径**。`dome()` 在这么近的地方取值仍高达 0.88，于是：

```
ΔH                = 1904 − 1666                       = +238
Δ基座（RAMP 西北高） = 1081.6 − 1058.4                   = +23
Δ交叉贡献         = 1666·dome(3144,10400,1.5) → +1443   （矮山把主峰抬起来）
                 − 1904·dome(3144,11200,1.5) → −1683   （主峰把自己抬得更多）
                                          小计      = −240← 把 H 差吃掉了
──────────────────────────────────────────────────────────────
合计                                          ≈ +21（实测 27）
```

**"矮山抬主峰"几乎等于"高山抬自己"** ⇒ 写在 `PEAKS[].H` 里的高度差
在落盘时被交叉贡献抵消掉九成。

⇒ 改法不是继续调 `PEAKS[].H`，而是**把峰高差交给峰顶小锥**
（`EXTRA_DOMES`，半径只有山体的 25%，交叉贡献小一个量级）：
**1050 / 300**，落盘高差 801 m。

### ③「取消鞍部」在几何上做不到字面意义

两座峰之间的山脊，**中点必然低于两峰** —— 不然中段会鼓成"第三个包"。
所以"取消鞍部"只能落地成"**把凹压到判据门槛以下**"：

- 鞍判据门槛 = `max(25 m, 3% × 全图起伏)`（`SADDLE_MIN_DROP_FRAC`）；
- v2.4.7 的 5.5% **高于**门槛 ⇒ 被标注；
- v2.4.8 的 **2.4% 低于**门槛 ⇒ 界面上不再出现鞍部标记，凹还在但读成
  "从主峰斜切到副峰的一个缓坡"。

⚠ **代价（用户知情后选定）**：鞍部这个部位在模板山地不再教，

## v2.4.7 改了什么（2026-10-04）—— 模板山地「山体填满图幅」

**只有模板山地改了**，丘陵与盆地未动。部位口径不变（峰 / 脊 / 鞍，谷与崖交给盆地）。

### ① 病根不是"太复杂"，是**山太小**

上一版按"就两座普通的山"重做后仍被嫌丑。这一版先量了三组数字，
结论是**之前的十几轮都在错误的层面上治**：

| 量 | v2.4.6 | 真实四座山 | 结论 |
| --- | --- | --- | --- |
| **山体占比**\* | **18.4%** | 74.2% ~ 81.5% | **差 4 倍** |

\* 山体占比 = 高于「最低高程 + 30% 起伏」的格点比例。真实值取贡嘎山 / 珠峰 /
梅里 / 太白山，同一口径、同一段代码算的。

v2.4.6 的四条边与四角全是 1620~1892 m 的**平原**，中心十字剖面是
`1798 1835 1844 1866 2613 3514 4771 5752 6330 …` ——
**4532 m 落差全挤在中央十几格里**，所以读图看到的是"绿盘上的两个锥"。

### ② 三条路都试过，两条走不通（这是本版最花时间的地方）

| 尝试 | 结果 |
| --- | --- |
| **收窄图幅**（20 → 12~16 km） | 山体占比升到 88%，但格距变小、单格落差变大，而部位判据用的是**绝对高差**（`RIDGE_TPI = 70 m`）⇒ **峰=0 鞍=0**。16 km 是硬边界 |
| 收窄图幅 + 同比压低落差 | 也救不回来：span16 ×0.35 ⇒ **脊=0**（落差一压，脊线的横向坡度直接掉到门槛下） |
| **放大峰半径**（5.6 → 11.2 km） | 山体占比升到 47%，但两座圆顶**并成一个宽顶**，局部凸起不足 ⇒ **峰全部消失** |

根因：**"山在图里显得大"要低起伏，而"判据认得出峰与鞍"要高差**，在同一格距下互斥。

### ③ 解法：宽山体 + 尖峰顶（`EXTRA_DOMES`）

把两件事拆开做，各由一个参数负责：

- **山体半径 ×2.0**（11.2 / 10.4 km）⇒ 负责山体占比；
- **峰顶小锥**（半径只有山体的 25%、高 770 m）⇒ 负责峰的局部凸起（TPI）。

⚠️ 小锥**必须用线性锥 `cone`、不能用余弦圆顶 `dome`**：
`dome` 在顶点处导数为 0，峰顶附近一片缓平，叠在斜坡上会读成
"**馒头顶上放了个蛋**"（出图实测，一眼能看出不对）。
`cone` 顶点就是尖的、离开峰顶立刻掉下去 —— 这正是 `cone()` 存在的理由。

### ④ 另加两处自然度（实测贡献有限，如实记录）

- **坡面噪声**（值噪声 + fBm，振幅 210 m、波长 3 km，沿主垄轴向压掉）；
- **两峰不对称**（迎缓背陡，35° / 210° 两个不同方位）。

⚠️ **关掉这两项，出图几乎看不出差别** —— 它们是"加了但作用有限"，
不是本版的主要功劳。主要功劳是山体放大。

### ⑤ 脊线从 6 条变 1 条（刻意的）

山体填满图幅后，主脊自然连成**一条** 39 点的干净线（v2.4.6 是 6 条 94 点）。
这符合"教科书示意图要少而清楚"—— v2.4.6 那 6 条里有一部分是被逼出来的：
山体太小，只能靠多而碎的脊线冒充复杂地形。

### ⑥ 顺带修掉两条一直红着的真机判据

| 判据 | 为什么一直红 |
| --- | --- |
| `I4 每一类数量 = min(3, 该类检出数)` | 模板山地自 v2.4.6 起**刻意清零陡崖** ⇒ 标注里没有 `cliff` 这个键（`undefined`），而期望值算出来是 `0` ⇒ `undefined === 0` 为假 |

## v2.4.5 改了什么（2026-10-03）

两件事：**部位标注改人工**（原来全自动，现在机器给起点、人可改），
**三个模板地形按"初高中生一眼能认出来"重做**。主脊仍是 1~2 道，没有加密。

### ① 部位标注：机器退位，人来定

峰 / 鞍 / 崖改成**人工标注**，存本地；山脊与山谷仍走机器（这两类本来就有
明确的地貌学判据，让机器扫更准，也省得人一条条描）。脊线条数**保持 1~2 道不变**。

- **机器检出降级成"默认候选"**，人工标注一旦存在就以它为准（`manualMode`）——
  不是在机器结果上追加，而是**接管**。
- 「采用机器结果」一键把机器检出收成起点，再手动微调。
- 「清空」与「删除本机这份」分开：前者把结果清成**空列表**，后者抹掉记录。
  两者必须可区分 —— 所以落盘是 `{version: 1, marks: [...]}` 而不是裸数组，
  带版本号才能拒旧格式；`null`（从没标过）与 `[]`（教师清空过）语义不同。
- 只存 `kind/i/j`，高程、落差、坡度、连线**读取时现算**
  （`elevationOffset` 会平移 `alt`，存下来就过期了）。
- 按样本 `tag` 分键：`mountain-zones.manualMarks.v1.<tag>` —— 换样本不串标注。

**顺带修掉一个真缺陷**：存储可用性以前只看"上次保存有没有失败"，
隐私模式（无痕窗口）用户是**标完第一个点**才被告知白标。现在改成**进面板就主动试写**
一个哨兵键再删掉（`storageAvailable()`），三档都覆盖：正常 / 读得到但一写就抛 /
访问 `localStorage` 本身就抛。

### ② 三个模板重做：目标从"像真的"改成"一眼认得出"

原来的模板是按真实 DEM 的思路做的，结果**不像地形**——山地读成"平地上的一个包"，
因为径向圆丘的四周等高；盆地的南侧环顶反而是全圈最高。

| | 改前 | 改后 | 怎么做到的 |
|---|---|---|---|
| **模板山地** | 四边几乎等高（最大高差 **132 m**） | 平面斜坡基座（西北 3661 → 东南 1968 m，四边高差 **1625 m**） | 径向圆丘改成有倾角的平面 |
| **模板丘陵** | 四边高差 **2 m**（读成一张平板） | 加 `TILT = 160` 缓倾斜基面，四边高差 **73 m** | 顶面才有连续起伏 |
| **模板盆地** | 南侧环顶 1319 m，**是全圈最高**（缺口跑到反方向） | 南侧环顶 **538 m，全圈最低**，两侧 876 / 991 m | 见下 |

盆地的南侧是**河流出口**（缺口 + 河道），这是"水往低处流"最直观的一课。
它原来错成两处：出口方位写成 `deg: 270`（=**北**，不是南），
而衰减窗口又写成 `smoothstep(W·cell, halfArc·R, outArc)` —— `smoothstep` 在
`x < e0` 时**返回 0**，于是中心线一点不衰减、只有两侧被压低，
**恰好把该最低的环顶抬成了最高**。改成 `1 - smoothstep(...)` 才修好。
另外原来的盆缘峰 `deg: 80` 与出口 `deg: 90` 只差 10°，**峰直接骑在缺口上**，
重排成 `[125, 181, 237, 293, 349]` 五个峰均布。

**新增第 7 节「教学可读性」常驻判据**（`scripts/template.test.cjs`），
按模板类型分别定阈值：山地要求"四边不等高"、丘陵要求四边有 40 m 以上起伏、
**盆地要求四周都要高于中心 ≥ 40 m**（这是"盆地"最直观的判据），
外加两条成对比较抓出口方位（南侧环顶比北侧低 ≥ 200 m、比其余方位最高处低 ≥ 200 m）。
成对比较不能省：实测把出口注入成 `deg: 270` 时，绝对量级那条会**因为盆地形状还在而继续绿**。

**弃掉的两条指标**（本来想用，量出来发现是恒真/反向的）：
闭合等高线层级数改前 13/4/7、改后 14/4/5，基本没动；
"图幅高差比"改前 17.2%/1.8%/3.9%、改后 19.9%/2.0%/2.6%，**盆地反而降了**。

### ③ 真机回归抓出的两个真缺陷（不是判据写错）

- **`view3d.ts` 的 `pick()` 地表分支没有图幅内检查**（平面分支本来有）。
  `altitudeAtWorld` 对图幅外坐标**钳制到边缘**，所以射向天空的射线也能穿过
  那张"虚假平面"，返回 `gy = 376` 这种越界坐标。修法放在两条分支汇合的出口。

  `downRef.current` 从没被记录过**（标注时"画剖面"是灰的，`pickMode === false`），
  于是 `onPointerUp` 里 `isClick` 恒 false —— **点沙盘毫无反应**。
  修法：`markKind` 也要进依赖数组，否则从 null 变成 `"peak"` 的那一刻
  回调还是旧版，**点第一下仍然没反应**。

### ① 标注不再压在山上，改成「拉一条线指出去」

你反馈的原话是「现在的标注会直接挡住地形本身，建议拉出一条线来指出去然后再标注」。
问题确实存在，而且能量出来：模板山地打开全部标注时，12 条标签**两两重叠 77238 px²**
（"山峰 4200 m"直接压在"山峰 3051 m"上），因为它们全都贴在自己锚点的正上方。

现在每条标签由一条引线拉出去：

| | 记号 | 文字标签 |
| --- | --- | --- |
| 三维沙盘 | 锚点处留一个**小圆点**（颜色随部位） | 甩到旁边，中间用**引线**连回来 |

灰色等高线上，单色线在深底上会糊掉。线头**钻进标签白底约 1.5px**（引线层压在标签之下），

### ② 甩的方向怎么定：三个坑，都是真机回归里量出来的

甩出去不是"随便挑个方向"，三条规则按优先级：

1. **方向 = 从"这一批锚点的质心"指向该锚点**（径向向外）。用质心而不是舞台中心：
   质心贴着地形本体，方向天然是"从地形往外"，而且随相机**连续**变化，转视角时标签不会跳位。
2. **径向会被舞台边挤回来时换方向**。锚点贴在画布角上时，径向指向屏幕外，标签被夹回
   锚点头上 —— **正好把锚点盖住**。实测四个角 4/4 全中。所以方向是试出来的：
   从径向起按 20° 一档往两侧转，取第一个"标签不压住锚点"的方向；角落里要转到 150°~180°。
3. **同样能让开时取引线更短的那个**。这一条是**看了真机截图才发现的**：第一版按
   "先试到哪个方向就用哪个"，结果 7 处陡崖的标签被一路推到舞台顶边，引线横跨半个屏幕。
   改成"同分取最短"后，最长引线从 251px 收到 137px。

第 2、3 条只影响"贴边的锚点"与"挤在一起的锚点"（模板山地那 7 处陡崖在同一条 380 m 断层上），
普通样本一个数字都没动。

### ③ 顺带补了一处防御：锚点坐标不是数字时不要硬画

真机回归里我的脚本把相机坐标（数组）当成对象用，算出 `NaN` 传了进来 —— `NaN` 与任何数比较
都是 false，于是"越界判定"全过、标签被堆到舞台中心，**而屏幕上只是"标注没跟着地形走"**。
现在非有限数的锚点一律按"不可见"处理（标签、引线、圆点全不画）。

### ① 五类地形部位可以一键标到图上了

侧栏多了一组「**地形部位标注**」，五枚按钮：山峰 / 山脊 / 山谷 / 鞍部 / 陡崖。
点一下，记号**同时**出现在三处 —— **三维沙盘、二维投影图纸、平面等高线图**。

| 部位 | 图上的记号 |
| --- | --- |
| 山峰 | ▲ 实心三角（带海拔） |
| 鞍部 | ◆ 菱形（带"下凹多少米"） |
| 陡崖 | ▼ 倒三角（带坡度与落差） |
| 山脊 / 山谷 | **线**（不是点） |

- **不是画上去的，是检出**：五类部位来自 DEM 的几何判据（山峰 = 非极大抑制 +
  相对起伏门槛；山脊/山谷 = TPI 高分位/低分位；陡崖 = 坡度 ≥ 65° 且单格落差有上限；
  鞍部 = 两峰之间那个低处，且有跨度与下凹幅度门槛）。按钮上直接写着本样本的**检出数**。
- **灰化判据不是"检出数 > 0"**，而是"这一类在本样本上**画得出来**"。
  例：川中丘陵检出 1 处山脊，但那一格是孤立点，骨架化之后一条线都没有 ——
  按钮亮着却什么都画不出来，比灰掉更让人困惑。灰掉时 `title` 里写明理由
  （"本样本检不出可连成线的位置（检出 N 处，太零散）"），**不静默灰**。
- **「全部标注」/「清空」**两枚快捷按钮；组标题显示「N/5 类」。

#### 脊线 / 谷线是**骨架化**的结果 —— 这件事在界面上写明了

山脊/山谷不是一个个孤立的点，而是**成串的格子**。直接把这些格子画出来会得到一条
"毛茸茸的带子"（宽度随坡度变），学生看不出"脊在哪"。所以做了三步：
闭运算补断点 → **Zhang-Suen 细化**成 1 格宽的中心线 → 剪掉短于 5 格的毛刺、把断口 ≤ 12 格的线接起来。

⚠️ **这带来一个必须说清楚的口径问题**：这条线是**细化**出来的，不是"检出的脊格本身"。
所以图例小字与侧栏提示里都写着：

> 脊线与谷线是**骨架化**的结果 —— 由检测出的格子（76 个脊格 / 63 个谷格）细化成线，
> 不是人工画的分水线；所以它表示"检测到的脊 / 谷在哪一段"，不等于严格的流域分界。

教学材料里这件事不能含糊：老师指着一条线说"这是山脊"，得知道它是**怎么来的**。

每座的半径与高度各按 `hash01` 抖动（仍然**不含随机数**，同参数逐字节可复现）。

### ③ 垂直夸张改成"坡度取向"，换样本自动给推荐值

以前垂直夸张固定 ×1，平缓地形（华北平原、模板丘陵）起伏被压得看不出来。
这一版按**该样本的坡度**自动推荐：

```
倍数 = tan(25°) / tan(第 90 百分位坡度)     然后钳到 [1, 20]
```

**为什么是"把典型陡坡抬到 25°"而不是别的**：目标是"让起伏看得清，又不让山变成假的"。
对真实山地，它本来就陡 ⇒ 推荐值就是 **×1**（不该再抬，再抬山形就失真、
垂直地带性的教学对比整个废掉）；对平原/丘陵/高原，抬高到 25° 才看得见起伏。

实测（默认值 = 推荐值）：

| 样本 | 推荐倍数 | | 样本 | 推荐倍数 |
| --- | --- | --- | --- | --- |
| 模板山地 | **1.000** | | 贡嘎山 / 珠峰 / 梅里 / 太白山 | **1.000** |
| 模板丘陵 | 2.140 | | 华北平原 | **20.000**（上限） |
| 模板盆地 | 1.840 | | 内蒙古高原 | 5.980 |
| 川中丘陵 | 2.420 | | 临汾盆地 | 2.050 |

- 界面给出「自动 ×N」档 + 一个「**自动**」小标 —— 让老师知道这个数是**系统给的**，
  不是上一版留下的旧值。手动拖一下滑块，小标就消失（表示"你改过了"）。
- 代价两条：`EXAGGERATION_MAX` **2.0 → 20**；滑块改成**对数刻度**
  （线性刻度下 0.5→2 只占 7.7% 行程，而 2→20 占 90%，手感完全不对）。
- **夸张倍数不进海拔** —— 它只乘渲染顶点的 Y，所有读数（海拔、等高线、带谱边界、
  剖面）都不受影响。这条从 v1.x 起就是硬约定。

1. **舞台角标把模板也写成「真实 DEM」**。模板山地的舞台角标印着

   现在分档：模板「解析生成 753–4200 m」/ 真实「真实 DEM …」。
2. **"图例说标了、图上什么都没有"**。`showParts` 是**用户的意图**，它跨样本保留 ——
   在模板山地上勾了「陡崖」，切到模板丘陵（一处陡崖都检不出）之后，那个 id 还留在数组里。
   于是：图例列着「陡崖 0 处」、按钮**灰掉却还是选中态**、组标题写「5/5 类」而实际只画出 4 类。
   现在显示层统一按"**有效选中** = 被选中 ∩ 画得出来"来算；
   **刻意不改 `showParts` 本身** —— 用户切回模板山地时，陡崖应当自己回来，而不是被悄悄丢掉。

### ⑤ 底层：修好骨架化自己的两个缺陷

这一版的脊/谷线是新写的 `skeleton.ts` 产出的。写完先做**独立测量**（而不是信注释），
量出两处**静默**错误 —— 两处都和自己的注释说的不一样：

- **`erode` 会把贴着图幅边缘的脊整条删掉**。"图幅外视为背景"的写法在腐蚀时
  变成"图幅外视为**前景**"，于是紧贴左边框的一道脊线**整条消失**（实测：满场
  腐蚀后 3364 格 vs 应有的 4096 格；贴边的那条脊 8 列全是 0）。改成
  腐蚀 = 对**补集**做膨胀，语义自然就对了（补集在图幅外是背景 ⇒ 反过来就是前景）。
- **`prune` 每次都会剩 2 格毛刺**。判"走到交叉口了"用的是**下一个格子**的度数，
  而 8 邻接里紧挨交叉口的那个格子自己就是 3~4 度 ⇒ 永远提前刹车。
  改成只数**没走过的**邻居。实测同一组毛刺（长度 1~7）剩下的格子：
  旧 `0,0,1,2,3,4,0` → 新 `1,0,0,0,0,6,7`（长度 ≥5 的本来就该留）。

两处修复**只**影响"贴边的脊"与"毛刺短桩"，模板地形两者都没有 ⇒
模板的骨架格数/线数**一个都没动**（回归里专门卡了这条，作为"改动波及面"的排他性证据）。

## v2.4.0 改了什么（2026-09-22）

> **上一版基线：v2.3.0**（8 个真实样本 · 修好"二维图纸被沙盘自己压住"的间隙几何）。
> v2.4.0 = **改名** + **新增三个「模板地形」**，真实地形一个没动。

### ① 游戏改名叫「口袋地形」

原名「真实地形山地 · 垂直地带性」。新名字少一个"山"字不是好听 ——
原名把**丘陵、盆地**挡在门外了，而这一版恰恰新增了这两种。

⚠️ **`gameCode` 没变，还是 `mountain_zones`**。所以老师手里的课程链接、邀请码、
已安装的那份数据都不受影响，只是显示名换了。改名落在五处：
`manifest.json` 的 `name`、两个 HTML 的 `<title>`、封面图横幅、游戏内标题、本文件与 README。

### ② 新增三个「模板地形」：模板山地 / 模板丘陵 / 模板盆地

**为什么加。** 真实 DEM 很好，但对刚上初中的学生，一座真山是"一团复杂的皱褶"——
要在上面指出"这里是鞍部、那里是陡崖"，他先得学会忽略大量细节。
模板地形是**为看清教科书那五个部位而专门构造的山**：山体填满图幅、特征尺度过关、
每个部位都在学生一眼扫到的地方。真实地形**全部保留**（8 个一个没删），
老师按学生的程度自己选。

| 样本 | 类型 | 图幅 | 海拔 | 局部起伏 | 检出的五类部位 |
| --- | --- | --- | --- | --- | --- |
| **模板山地** | 山地 | 20 km | 753–4200 m | 500 m | 峰 3 · 脊 76 · 谷 63 · 鞍 2 · **崖 7** |
| **模板丘陵** | 丘陵 | 20 km | 146–596 m | 88 m | 峰 6 · 脊 72 · 谷 43 · 鞍 4 · 崖 **0** |
| **模板盆地** | 盆地 | 40 km | 400–1949 m | 797 m | 峰 6 · 脊 43 · 谷 50 · 鞍 1 · 崖 5 |

- **模板山地把五类部位一次摆齐**：两座主峰夹一个鞍部（峰顶间距 82.2 格，落在鞍部的
  最大跨度阈值 90 格之内，所以"两峰之间那个低处"确实会被认成鞍部）；两条山脊从主峰
  甩出去；山谷顺着坡切下来；陡崖是一道 380 m 的直立断层（水平位置刻意卡在
  `x = 72.5` 两个采样点之间，见下"台阶的相位"）。
- **模板丘陵没有陡崖，而且这是对的**：丘陵最陡处实测 **53.5°**，而陡崖门槛是 **65°**。
  想让它出陡崖，得把相对高度推到 300 m 以上 —— 那就不叫丘陵了。
  所以"丘陵不含陡崖"是**地形本身的属性**，不是这一版偷懒没做。
- **模板盆地不是"一个坑"**：盆底是一片平坦底盘，四周一圈山地（外环比中心高 788 m，
  8 个方位全部成立）。学生能一眼看出"四周高、中间低"，也就看出"盆地"这个类型
  和"鞍部"这个部位不是一回事。

三个模板都是**解析函数生成**（圆锥 / 圆顶 / 高斯脊叠加），**不含任何随机数** ——
同参数跑两遍必然逐字节一致。这不是洁癖：正因为可复现，我们才能把生成结果的
sha256 钉成"只读契约"，形状被谁手改一下立刻变红（见「验证」）。

### ③ 入口：同一个选择器分两组，模板排在前面

打开游戏**默认落在「模板山地」**（先认部位、再上真山，符合教学顺序）。
模板那一组带一句提示：*不是真实地点，是为了看清五个部位画出来的样板*。
真实地形按五类类型标签筛选，分组完全不变。

### ④ 模板地形不画中国地图，换成一张说明卡

模板是示意地形，**没有省份可标**。硬套一张中国地图 + 一个红点，等于告诉学生
"这座山在四川"——**是错的**。所以这一栏对模板换成说明卡：这张图为什么长这样 /
五类部位在这张图上分别在哪 / 它和下面真实地形的分工。
地理位置栏对模板显示「示意地形」，真实地形照旧显示省份与到省几何重心的距离。

### ⑤ 四项参数对模板一样生效

纬度 / 季节 / 海拔偏移 / 垂直夸张**一个都没锁**。模板地形同样能讲垂直地带性：
把模板山地（峰顶 4200 m）抬到雪线之上，带谱照样收紧、径流照样归零。
"简化的是地形形状，不是模型"。

### ⑥ 图鉴从 8 张卡片变 11 张，模板卡片带「模板」角标

角标是为了让人**一眼分清哪些是编的、哪些是真的** —— 教学材料里这件事不能含糊。

### ⑦ 底部来源署名分两种

| 样本 | 署名 |
| --- | --- |
| 模板 | 解析函数生成（示意地形，无随机数、可逐字节复现） |

### 一个被推翻的旧结论（记在这里，免得下次又推一遍）

v2.2.0 的文档里我写过一句**"丘陵没有山脊"**。这一版做模板丘陵时按它构图，
结果脊点占比 **0.00%**、谷点 0.07%，测试直接红。

量了一遍才发现：那句话量的是**我自己的构图**（几个圆顶摆在平板上），**不是丘陵本身**。
补上两道窄梁（`RIBS`）之后，脊点从 0 变成 **72 个**，与谷的 43 个同量级。

**教训**：把"某个地形类型有没有某个部位"写成结论时，必须问一句
"我这是量的地形，还是量的我画的那张图？"

### 一个静默陷阱（值得别的游戏也看一眼）

给模板填的地理坐标是**占位值 30°N / 105°E**。这个点是**成都附近，在中国国境线以内**——
于是"这个坐标在中国境内吗"这类校验**全部通过**，界面上什么错都不会报。

真正的危险是另一条链路：`locationByTag(tag)` 在查不到时会**静默回落**到
`SAMPLE_LOCATIONS[0]`（贡嘎山 / 四川省）。只要有人忘了走 `isTemplate` 分支，
模板山地就会一本正经地显示"四川省"、并在中国地图上点一个红点 ——
**数据错了、位置偏了，屏幕上一点异常都没有**。

所以 `locmap.test.cjs` 新增了第 6 节，把这条**当成契约钉住**：
模板地形不在 `locations.ts` 里、lat/lon 必须是占位值、`locationByTag` 的回落是哨兵值。
下一次谁动这块，测试会先红。
